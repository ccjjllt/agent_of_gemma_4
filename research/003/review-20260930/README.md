
- `trace_review.json`：48 个面板 `result.json` 和 48 条完整 trace 的观察、工具错误、输出 token 分布及原件 SHA-256。输入来自 `results/003/recovered-20260930/`，该目录受 `.gitignore` 排除；换机器须先恢复原件。脚本显式记录缺失，不补零。

## 分类与执行错误改变了下一阶段优先级

面板历史标签为成功 6、localization 11、edit 8、budget 14、env_verify 9；标签保留原样。其中 localization 为 **11 次/7 题**，budget 为 **14 次/8 题**。两类共 25 次/15 题，全部无最终生产修改，23 次接近 300 秒。它们是互斥研究标签，但“定位、工具执行、耗时”本身可能重叠，不能据 11/19 宣称已识别纯定位根因。全部 48 次中 26 次没有最终生产源码变化。

原件中的三个关键纠正：

- **rich_3942-B**：约 88.84 秒因 `ContextWindowExceededError` 结束。32768 上下文预留 16384 输出，输入至少 16385，超过容量；不是五分钟耗尽。
- **rich_3130-A0**：291.48/299.51 秒对 `rich/markdown.py` 的两次编辑都返回 `FileEditError: old_string not found`；是编辑尝试失败，不能写成成功修改后补丁丢失。参数含多余反斜杠，但仅凭此不能把原因全部归给模型或 harness。
- **fastapi_14873-B**：43 次 `FileReadError`，其中同一个含 `,start_line` 残片的错误路径参数连续重复 33 次，最后空提交。它已经指向 `fastapi/routing.py`，不能简单解释为不知道文件在哪。

48 条 trace 中，以生产目录前缀识别的 `edit_file/write_file` 共 **99 次尝试，25 次返回 ok，74 次返回工具/参数错误**。74 次错误中 **64 次集中于同一题 fastapi_14605 的 A0/B**，不是 74 个独立失败；这些结果不证明某个新工具一定有效。命令行也能改文件，此计数只覆盖这两个显式工具；`ok` 不代表代码正确或修改进入最终补丁。

CSV 的 `first_source_edit_at` 是首次**编辑尝试**，不是首次成功。审计另存 `first_successful_source_edit_tool_call_at`，不覆盖历史字段。两组都有成功工具编辑的 9 个配对，B−A0 首次成功编辑时间均值 −8.33 秒、中位数 **+11.11 秒**；这是按事后成功事件筛选的子集，不能用来宣称因果提速。

## 8192 输出上限的证据与限制

1437 个记录到的 Agent LLM 步都有 completion token 用量，逐条 trace 的总和全部与 `final_metrics` 一致；97 个 system/user 步不属于这些 LLM 步。

| 记录范围 | LLM 步数 | 最大 completion | P95 | P99 |
|---|---:|---:|---:|---:|
| 全面板 | 1437 | 6114 | 1062.6 | 2255.4 |
| 6 条成功轨迹 | 205 | 1494 | 767.2 | 1410.0 |

没有已记录调用达到 8192；有两步超过 4096。结合已证实的上下文容量错误，**仅将 `max_output_tokens` 从 16384 改为 8192** 是有依据的首个单变量容量消融。历史分布并不保证未来输出不会截断，也不保证轨迹和成功率不变。失败的溢出调用没有完整输出；trace 无独立 compaction 调用标识，不能声称覆盖所有压缩调用。未导出模型思考全文。

建议先核验实际生效的推理参数、输入/输出容量和工具参数传输，再冻结共同环境并对定位方案做配对。先用已暴露任务做运行与验证校准；对定位比较同时记录候选文件覆盖、首次成功编辑、工具失败、最终补丁与有效验证结果，避免单一失败标签替代因果诊断。当前证据不支持直接同时更改思考预算、提示词、图检索与时间预算。

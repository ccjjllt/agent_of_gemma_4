## 四问合同（复现前必写，全绿或意外通过后必答）

1. 当前观察：这个复现是否真的包含 issue 的触发前提？
2. 关键区别：只改变哪个输入/配置，就应从正常转为异常？
3. 预期差异：异常类型、返回值、格式或分支应出现什么区别？
4. 已有证据：在哪个源码分支 / 实际输出中看到了它？

## 规则（可执行）

- 全绿或意外通过时，先查是否遗漏故障子条件；最多补一组最小对照（一个目标断言 + 一个邻近对照），不批量追加同类脚本。
- 相同输入、相同输出、无源码变化重复两轮后，下一动作必须是新增信息（新触发条件 / 新分支证据）或局部修改；禁止第三次原样重跑。
- 依赖 / 夹具 / 导入报错 ≠ 复现成功；继续用源码证据推理，不为验证而修环境。
- 临时复现只放沙箱临时目录，不进最终补丁；提交前检查 diff 文件集合。
- 通用语句命中、文件读过，不算理解证据或分支覆盖。
- 不加 LLM 裁判；不预装参考答案、裁判测试或离线标注；casebook 的事后标注不得进入候选输入。

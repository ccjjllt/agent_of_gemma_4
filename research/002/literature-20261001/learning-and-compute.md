# 推理预算、验证反馈与学习数据：研究交接

调研日期：2026-10-01（Asia/Shanghai）。范围：5 篇论文及作者发布物；只读联网核查，未运行模型、训练、远程实验或提交。本文的“论文结果”是作者报告；“迁移判断”和 H1–H4 是本项目待验证的设计，不是已经获得的性能增益。

## 决策

下一步最高信息价值的工作是：**先用 CPU 把现有轨迹变成可验证的状态转移和失败恢复案例，再研究五分钟内怎样更早获得有效修改、避免丢掉已获得的证据。** 近期不启动训练，不扩展 AMD/TPU，不照搬 best-of-N、多 Agent 或树搜索。

固定约束：Gemma 4 31B、每题 300 秒、模型调用串行、当前 0C 保留 `max_tokens=16384`。16K 是单次输出上限，不是必须消耗的思考量；本调研不建议为了挤入更多调用而先砍该上限。必须分别核算输入占用、模型输出、工具耗时和真实状态变化。模型有思考时间，工具返回中又有足够的新证据，二者才可能共同产生收益。

SWE-bench 的论文得分不能换算为本比赛分数，更不能据此预测金牌线。模型、任务、工具、候选数量、上下文、执行环境和时限均不同。

### 1. CodeMonkeys：测试与候选的联合演化

[论文 v2，§2.2–2.3、附录 B](https://arxiv.org/html/2501.14723v2)；[作者代码](https://github.com/ScalingIntelligence/codemonkeys)。

它让测试先在未改仓库上暴露问题，再让补丁与测试共同迭代；选择阶段把生成测试用于交叉评价，再对较少候选做进一步区分。初期串行迭代有明显收益，更多候选则增加选择难度。论文清楚区分 recall、coverage 与最终 score。注意作者网站摘要写 57.7%，论文 v2/表 2 写 57.4%；本记录采用论文版本，不混合数字。

**迁移判断：**最值得移植的是“测试究竟区分了什么”这一证据要求。repro 报错、测试退出 0、补丁正确三者不能划等号。五分钟内，应优先比较同一轨迹已产生的两个不同源码补丁，而非另开完整尝试。同一坏测试导致两个候选都通过不构成投票证据；候选回放前必须重置到相同 base。现阶段只整理可回放清单，不下载环境或执行外部测试。

### 2. SWE-Gym：成功轨迹有用，但自采样并不保证自我改进

[ICML 2025 论文页面](https://proceedings.mlr.press/v267/pan25g.html)；[全文 §4.2、§5.1、附录 B](https://arxiv.org/html/2412.21139)；[作者仓库及复现实验入口](https://github.com/SWE-Gym/SWE-Gym)。

OpenHands 路径中，491 条成功轨迹平均约 19 轮/19K tokens；32B 的循环率原先很高，监督微调普遍减少循环。反面结果同样重要：该路径加入 868 条 on-policy 成功轨迹后，Lite 从 15.3% 降到 8.7%。论文其他 scaffold 的自我改进结果不同，不能笼统说“自训练无效”。Verifier 使用成功/失败混合标签；选择结果仍明显低于候选中至少一个正确的上限。

**迁移判断：**P003 轨迹是审计和数据设计的起点，不足以证明可以直接训练。失败轨迹中也可含有效定位、正确编辑及恢复动作；成功轨迹中可含无效循环和污染补丁。应分开收集“下一步动作监督”和“整条补丁结果监督”，禁止把最终失败整条复制为动作目标，也禁止因最终成功就复制全部低效行为。

### 3. SWE-smith：可执行、多样、去重比一味收集更多轨迹更重要

[论文 §2–4、附录 F](https://arxiv.org/html/2504.21798)；[作者仓库](https://github.com/SWE-bench/SWE-smith)；[作者项目页，2025-04-30](https://swesmith.com/)。

作者通过制造能触发已有测试的缺陷，扩大任务与仓库多样性；训练集只取通过验证的专家轨迹，每题最多保留 3 条，避免容易题反复占样本。不同合成缺陷策略质量不同。Python 训练后的多语言结果仅 8.4% 对基础模型 6.5%，提示行为提升不等于跨领域泛化。当前仓库展示的 52K 任务/250+ 环境是后续发布状态，不替换论文的 50,137/128。

**迁移判断：**近期准备数据契约和小规模人工审计，不启动合成大流水线。以后若训练，优先按 repo/commit/issue/源码 diff 去重，并检查测试能否验证目标行为、是否重复同一简单模式。环境可复用只是一项工程优化；不同 commit 的依赖和测试有效性仍要核验。其仓库要求 Docker/Linux，不应声称本机 macOS 已可直接复现。

### 4. SWE-Reasoner：阶段检查值得借鉴，收益不能归因于“多想几秒”

[论文 §2–3](https://arxiv.org/html/2503.23803)；[作者仓库](https://github.com/yingweima2022/SWE-Reasoner)。

作者把仓库理解、定位、补丁生成视为关键决策点，并训练过程/结果评价器；训练时筛选定位与参考修改相符的轨迹，验证复现程序在参考修复前后有区分力。删去 LongCoT 的消融也改变了教师和目标生成方式，因此不能把 37.6% 对 28.8% 全解释为延长原模型输出。查询日仓库仍写“Code is coming soon”，公开数据不等于端到端可复现代码齐全。

**迁移判断：**保留 0C 的 16384，先测“证据已经到手但没有转为修改”的阶段。可以只在失配编辑、重复无变化命令、验证信号矛盾时做一次有界恢复。当前不训练 PRM；用参考补丁位置做离线弱标签时必须标明它不覆盖合法替代修复，且绝不能传给运行中的模型。

### 5. SWE-rebench V2：负样本必须先确认不是坏环境

[论文 v2，§3.3–3.6、§4.3](https://arxiv.org/html/2602.23866v2)；[作者数据发布](https://huggingface.co/collections/nebius/swe-rebench-v2)；[作者基础设施与代码说明，2025-11-07](https://nebius.com/blog/posts/infrastructure-behind-swe-rebench)；[作者 SWE-bench fork](https://github.com/swe-rebench/SWE-bench-fork)。

该工作把测试状态结构化为 pass/fail/error，并通过参考修复前后对照和三次重跑筛除不稳定任务。PR 合成说明仍有泄露风险，作者在 509 例审计中报告 23.0% 有某种泄露、2.4% 有显式答案泄露。其主要贡献是任务与标签可信度，并非一个已证明优于本项目的修复策略。第三方 `EnvCommons/swe-rebench-v2` 是环境封装，不应冒充作者实现。

**迁移判断：**训练与能力分析不能把 setup error、context overflow、编辑工具失配、真实 assertion failure 都压成同一个负标签。已知金补丁也失败的环境，只能产生环境诊断样本，不能产生“此源码补丁错误”的标签。外部数据先只查许可、元信息、去重与潜在比赛重叠；不要加载本项目 heldout 内容或为补数据读取其答案。

## 待验证的四个假说

以下均为本项目提出的组合与约束化设计；论文没有验证它们在 Gemma 4 / 300 秒条件下有效，也不主张学术首创。

| 假说 | 机制与反证条件 | CPU 先交付什么 | 未来最小在线对照 |
|---|---|---|---|
| H1：错误恢复比一般“别重复”提示更有针对性 | 相同无变化动作不会自动禁止；遇到 `old_string not found` 等可修复错误时，要求先读当前精确片段再重试。若主要失败不是可恢复工具错误，或恢复本身挤占有效修改，则拒绝推广。 | `recovery_events.jsonl`：错误、当时可见证据、下一步动作、是否真正成功、恢复耗时。每个 case 附原始 trace 索引。 | 0C 与 0C+仅错误触发恢复；同题同预算，比较成功源码编辑/终局成功/新增开销。 |
| H2：有效验证比更多验证更稀缺 | 验证动作须关联补丁哈希与具名断言；把未改变代码/测试/环境的同一复现重复视为低增量，而非把全部重复一律惩罚。若重复是等待服务或随机性检查，则单列。 | `validation_ledger.jsonl`：测试身份、代码状态、退出类型、是否触达断言、前后对照是否存在。只整理已有输出；缺少 base 对照标 unknown。 | 在足够剩余时间且已有补丁时，最多选择一次已有窄测试补足缺失证据，不强制每题先写 repro。 |
| H3：同轨迹已有补丁的选择有低成本潜力 | 只比较已经实际生成的不同源码状态；禁止从未来步骤或裁判结果回灌在线。若几乎所有轨迹只有一个候选，选择器没有上限空间，应停止。 | `candidate_timeline.jsonl`：每次成功源码编辑后的哈希、来源步骤、是否可重建、当时测试。先计算有≥2不同候选的题数，不能把 A0/B 多次运行并集当作单次可达上限。 | 先 CPU 冻结回放核验候选是否存在“早期可用、末期退化”；有证据后再研究末轮保留/选择，不新增整条采样。 |
| H4：训练应学“失败后如何恢复”，而非只学最终成功的外形 | 制作输入仅含当时观察的状态→动作对，成功后状态必须可证。若只删失败动作而保留原后续状态，会生成因果不成立的伪轨迹。 | 一个小型审计集与 schema：真实成功片段、真实恢复片段、失败但未验证原因的片段分开。暂不拼接训练文本，不微调。 | 日后若有足够独立题与资源，先做低成本动作模仿/离线质量审计，再决定是否值得模型训练。 |

H1 是先行优先级；H2 决定“验证慢/无效”是否实际阻断；H3 先做候选存在性审计；H4 是延后训练的准备。若 CPU 审计不支持对应问题普遍存在，就停止该支线，不因论文故事好听继续消耗 GPU。

## 重新实现时的数据契约

实现以下模块即可检验这些假说，不需要先复制论文 agent：

1. `trajectory_reader`：将 ATIF steps 和工具回包对齐；保留 `source_file_sha256/step_id/tool_call_id`。时间用同一 run 的单调相对时间；缺值不补猜测。
2. `state_reconstructor`：仅成功编辑更新文件状态和补丁哈希；失败编辑不能计为首次修改。如 run_command 可能修改文件但没有内容证据，状态标 `unreconstructable`，不假装获得准确候选。
3. `evidence_classifier`：分别输出 `tool_outcome`、`source_change`、`verification_outcome`、`environment_validity`。一次运行可同时有多个状态，不能只保留一个 primary cause。
4. `budget_accountant`：输出每阶段的 wall time、调用次数、已记录 token 数、新读范围、成功编辑和具名测试变化。token 缺失标 unknown；不能用字符数冒充 tokenizer 计数。
5. `case_exporter`：导出人工可核查的“观察→动作→回包→真实状态变化”。把 runtime 可见字段与 offline/reference 字段分表，防止参考答案混进未来 agent 输入。

推荐最小记录字段：

```text
run_id, attempt_id, task_id, repo, base_commit, variant
trace_sha256, step_id, tool_call_id, elapsed_seconds
visible_input_refs, action_kind, action_fingerprint
tool_exit_class, edit_applied, source_diff_hash, temp_diff_hash
test_id, tested_diff_hash, assertion_reached, test_verdict
environment_validity, reference_verification_status
next_observed_action, recovery_success, confidence, reviewer_note
```

`reference_verification_status` 只能出现在离线分析域；运行中验证器只能使用题目正常暴露的源码/测试/工具输出。`test_verdict=unknown` 是有效状态，不能强制二分类。`edit_applied` 必须来自工具成功回包或真实差分，不能只看调用参数。

## CPU 阶段验收与下一次 GPU 的使用顺序

CPU 阶段首先产出可追溯的事件账本及人工抽查，不声称提高解决率。至少覆盖：失配编辑、正常成功编辑、重复复现、真实断言失败、setup error、上下文异常、主动提交，以及无补丁超时；用于验证的是状态识别是否正确，而不是复述实现的形式化单元测试。

最重要的三个统计量是：从首次相关证据到首次成功源码编辑的时间；同一工具失败后的真实恢复比例与耗时；验证调用中能关联准确补丁且产生可解释断言变化的比例。参考文件命中只是定位代理指标，不能等价为理解正确。把 300 秒超时作为删失数据；不能拿成功样本的平均耗时外推所有失败题。

离线回放只有已记录路径，无法知道模型在新提示/新工具回包下会怎样行动。通过重放“删掉重复动作”得到的虚拟节省秒数最多是机会估计，**不是因果收益或预测成功率**。不得用这种估计提前宣布方案战胜 0C。

资源恢复后，依次验证：0C 控制组可重复运行 → 单一恢复机制 → 同预算配对小探索 → 冻结变体后扩大面板。16384 输出上限、模型、采样与环境保持共用；比较终局通过数，并辅以成功修改率、可解释验证率和 context/timeout 分布。训练、生成新任务、额外评分模型都单独立项，不捆绑进首轮，heldout 继续封存。

## 交接结论

这五项工作的共同启示是：更多计算只有在观测可信、反馈有区分力、轨迹质量受控时才有意义。本项目当前更适合把预算用在“获得下一条有效证据并转成真实修改”，而不是增加候选数量。近期交付物应是可复用的状态重建与恢复数据，不是一个未经验证的新大 agent 框架。本文只完成文献与实现规格，H1–H4 尚未实现或实测。

# P007：从行为证据到实际修复的前沿研究

检索日期：2026-10-17。对照了 [006研究](../../006/frontier-20261013/report.md)、[E2机制分析](../../006/reference-pair-20261013/mechanism-analysis.md)与[12B CPU结果](../../006/12b-cpu-adaptation-20261013/results.md)。本轮精读六项一手研究，版本均早于检索日；论文、作者仓库和数据元信息通过Web核实。未运行GPU、训练、付费教师或基准实验；未下载模型权重或数据集、未读取heldout、未新增测试与工程检查脚本。文献成绩不外推为Gemma收益。

## 结论与排序

**最值得改变的是数据目标：从“失败调用后恢复格式”扩展到“判断哪条证据有效，并把已确认原因落实为生产修改”。** E2已有两个不同问题：弱见证把错误行为判成成功；取得目标代码或原因后，仍反复写复现而不修。单纯增加调用数、检查清单、反思角色或训练长度都不能直接解决这两个问题。

| 顺序 | 本项目研究对象 | 本轮证据改变了什么 |
|---|---|---|
| 1 | 行为判据与一次实际修复的成对材料 | 复现脚本执行成功、补丁可应用和目标行为正确必须分开；先检查是否真正执行到要求的行为 |
| 2 | 取得充分证据后的下一动作 | 短提醒可以作为干预候选，但不能以“遵守流程分数”替代最终修复；不强迫每题走完整长流程 |
| 3 | 12B真实数据SFT后，回到官方CT运行同一任务 | NF4训练loss降低只证明训练侧拟合；模板、状态、工具协议和数值量化都可能造成迁移损失 |
| 4 | 与目标函数相关的已有调用实例 | 借鉴现有用例中的API用法，减少复现自身错误；暂不搬入需数分钟预处理的在线覆盖率管线 |
| 放弃本阶段 | 每题启动“复现生成器＋裁判＋多候选选择＋常驻技能”的组合 | 未证明本地裁判能区分正确行为，额外流程可能耗尽300秒；缺乏同预算Gemma证据 |

## 1. SWE-Tester：格式学会了，行为验证仍可能很弱

[v2，2026-09-08](https://arxiv.org/html/2601.13713v2)，§3–6、A.6/A.9。Gemma-3-12B、Qwen2.5-Coder 7/14/32B、Llama3.1-8B；41K PR材料经16K过滤实际训练23K，2 epochs、2–8 A100。433题SWT Verified中Gemma补丁可应用率85.91→90.99%，真正fail→pass复现0.92→8.08%。训练给gold定位的旧源码/测试文件；部署检索后每题32候选。Qwen LoRA消融r8/α16有效，但用oracle定位，不是Gemma量化LoRA证据。该文评价复现能力，不是完整修复率；正文Qwen主结果与A.6 oracle表数值相同，未由原件进一步消除协议歧义，不据此算定位收益。

[作者仓库](https://github.com/adityasoni9998/SWE-Tester)有数据准备、训练和推理目录；[作者HF数据](https://huggingface.co/datasets/adityasoni17/SWE-Tester)可见四个子集，字段含base_commit、problem_statement、source_code_files、source_test_files和patch。页面未显示清晰的数据许可字段，仓库首页也未见明确代码LICENSE；论文A.11称原仓库为MIT/Apache/BSD，不能据此认定聚合数据可无条件再分发。只查看页面元信息及其自动呈现的train预览，未批量下载或加入训练集。

**迁移判断：**可以把它列为新的PR来源候选，但先在许可清楚、独立于比赛仓库的少量issue中重建旧状态。我们需要的目标可是一条内联行为命令及实际源码编辑，不需要新增测试文件。不能照搬gold定位训练后宣称端到端能力；若提供人工定位，就把任务标为“定位已完成的修复子任务”。现有click/pydicom两条只证明真实重放和标签编码，不能承担此类泛化结论。

## 2. TestPrune：相关的既有用法有价值，完整在线管线太贵

[v2，2026-05-08](https://arxiv.org/html/2510.18270v2)，§4–5，现题名 *Can Old Tests Do New Tricks for Resolving SWE Issues?*。使用GPT-4o/Sonnet3.7，500 Verified/300 Lite；Agentless已有候选上，仅更换回归子集使Sonnet Verified50.8→52.0%，再结合Otter复现集合达55.6%。新增Agent对照为Trae/Sonnet3.7单次65.0→70.2%、SWE-agent/Sonnet4的Lite56.7→62.0%。不是同300秒预算。反证很明确：复现对照中TestPrune独有成功49题，原planner独有35题，相关上下文也会误导；仅提高代码覆盖率不保证断言有效。

[IBM作者仓库](https://github.com/IBM/Issue-Test-Localizer)明确Apache-2.0，提供四阶段实现、示例及结果入口。README称单题完整预处理约3–5分钟，且不含镜像构建；全500题约两天。论文的额外$0.02/$0.05是模型API费用，不能替代墙钟预算。没有读取其基准轨迹或运行管线。

**迁移判断：**只先借用“从现有用法确认API/fixture”的机制。在独立开发issue中，由已定位函数查一个已有调用实例，再运行一条满足题意的短命令。我们E2的整数传给Rich单元格、错误FastAPI回调入口，属于应先避免的复现自身错误。读取现有用例不等于新增测试工程；也不将同一库的全部用例喂给模型。

## 3. From Plan to Action：提醒有实验支持，流程合规不是修复目标

[v3，2026-08-07](https://arxiv.org/html/2604.12147v3)，§3/5.3/6。SWE-agent配GPT-5 mini、DeepSeek V3/R1、Devstral24B，21,120轨迹、八种计划变体，主集497 Verified。每五步重注入原计划有一致改善；标准计划重复三次以分析随机性。但Pro分析从266 Python题筛到至少一个模型能解的31题，有选择偏差；正文未给统一300秒/费用对照。GPT-5 mini的流程合规与成功反而弱负相关；“先patch后复现”的V3表面改善在控制随机性后近乎消失。不能据此强制所有题固定阶段。

[作者论文指向的Zenodo v3](https://zenodo.org/records/22047054)于2026-08-21发布，1.3GB压缩包，含轨迹和分析；页面的License值为空，未核实包内代码/数据许可。论文CC BY4.0不自动覆盖包内数据。本轮只读元信息，不下载基准轨迹。IBM的[10月12日项目页](https://research.ibm.com/publications/from-plan-to-action-how-well-do-agents-follow-the-plan)仍写旧版16,991轨迹，本报告采用arXiv v3的21,120。

**迁移判断：**对“原因已可见但未实施”的状态，测试一次短提醒更有价值，例如要求指出尚未改变的生产行为并执行最小修改。提醒不能泄露未来补丁，也不应反复索要计划文档。需要实际记录下一动作是否为有效源码编辑、后续行为是否改善、是否撤回正确修复。只有提醒臂用额外调用时，必须扣除剩余预算；论文中的每五步不是我们的已验证频率。

## 4. Kimi-Dev：局部编辑能力可作为先验，但小SFT并非凭空起效

[v1，2025-09-27](https://arxiv.org/html/2509.23045v1)，§4、A、E.2。Qwen2.5-72B先经历约150B-token中期训练与Agentless SFT/RL，再用5,016条SWE-smith轨迹适配，训练64K、推理128K/100轮，Verified pass@1为48.6%。100–2,000条子集消融显示初始化影响适配；某SFT先验在200条时退化。不能把结果归因于“5K数据即可”。作者还明确展示TestWriter奖励假阳性：漏测多处行为/代数性质，使验证器把不完整测试判正确；阶段后续收益混合了反思与写测试，未独立识别因果。

[作者仓库](https://github.com/MoonshotAI/Kimi-Dev)有Agentless推理实现和模型入口；[LICENSE.md](https://github.com/MoonshotAI/Kimi-Dev/blob/master/LICENSE.md)写明模型受Qwen许可约束，其下采用MIT，不能简称无条件MIT。未确认完整150B训练语料可直接下载。论文A中的合成轨迹会注入反思语句并转写PR提交，不是天然真实执行记录。

**迁移判断：**我们可研究“当前源码＋已观察行为→一次真实编辑”的短监督；输入能否支持目标动作需要独立说明。公开提交可以作为目标，但提交后信息不能混进声称发生在修复前的reasoning。保留原始thinking、工具回包和分叉来源；确实压缩时先定义部署入口，并从那个入口重新续跑。该证据没有支持把两条局部重放扩成大量切片，再当成大量独立任务。

## 5. QATFactory：训练数值必须对应实际部署运算

[v2，2026-10-01](https://arxiv.org/html/2609.39223v2)，§3.3/4.1/4.3/4.4。研究8B–230B的NVFP4/MXFP4/Q4_K；多数QAD用8 H100、8K序列，QARL用4 B200。Qwen3.5-9B的量化训练策略因格式而异；r16 LoRA-QAD在8K仍需57.19GiB，增大rank未稳定增益。关键实现是先合并LoRA再量化，即DQ(Q(W+BA))；不是固定量化基座外加BA。结果在目标推理引擎测量，未研究Gemma固定CT上的NF4适配器迁移。论文CC BY4.0；[作者指定仓库](https://github.com/QATFactory/QATFactory)在本次Web与原始文件访问中失败，代码许可与当前可复现完整性未核实。

**迁移判断：**本项目采用另一种运算：训练近似为DQ(NF4(W_QAT))x＋BAx，部署为DQ(CT(W_QAT))x＋BAx；两侧冻结权重及误差不相同。实际CT还包含引擎路径差异，上式只是线性层概念说明。我们固定的[12B CT config](../../006/official-data-20261013/models/12b-ct-config.json)为对称4-bit、group32；[当前训练配置](../../../training/configs/sft_12b_qat_nf4.yaml)为NF4。这不是模板一致就能消除的差异。

近期不实施QATFactory式重合并/重导出基座，也不承诺训练原生CT量化梯度。先用已固定QAT来源训练一份小adapter，再在官方CT上实际加载并对比base/adapter。若训练动作似然明显提高而CT行为不变，才值得分辨容量、数据、模块映射或数值迁移；不能立即归罪量化。CPU微型LoRA梯度/导出通过不构成这一步证据。

## 6. Agent Skills Can Be Harmful：常驻流程可能制造额外工作

[v1，2026-08-12](https://arxiv.org/html/2608.11888v1)，§III/V/VII。OpenCode1.15.1＋Opus4.6，在84个SkillsBench和490个SWE-Skills-Bench任务上比较无技能、原技能及至多五个相近技能；提炼307个失败/成本退化案例。182个效率退化中67个源于过度验证、30个源于重型实施流程。它是筛选后的负案例归因研究，20,664是潜在比较对数，不是独立任务或完整运行次数；没有Gemma/同预算消融。人工排除歧义案例、单模型生态限制推广，不能用307推算技能总体伤害率。

论文CC BY4.0；未核实作者代码/数据发布，搜索到的同名SkillTriage不是本论文实现。我们已有的E2技能调用为零，因此该论文不能解释E2失败“由技能造成”。它只支持暂停扩大技能体系，先确认一个短反馈确实改变动作，并把新增步骤的墙钟成本算进对照。

## 30小时/周量级内的可迁移研究

以下是本项目建议，不是文献已经验证的配方，也不启动实验。额度用实际账号单位核算：4卡的一小时不能未经核实直接记作一额度小时；下载、冷启动、模型加载和失败消耗均计入实际记录。

**先做CPU材料，避免把弱裁判带进学习。** 从新增、独立、许可可核查的训练候选中挑三个机制，不使用E2三题的修法当新训练答案：语义对象仍错但脚本不抛错；复现自身API错误；已定位原因却没有生产改动。对每个候选保留issue、实际buggy commit、当时源码、工具回包、原始推理和后续动作出处。先人工确认命令是否调用到目标行为，错误是否来自目标而非环境/见证构造。使用一次性内联Python/Shell，不保存新的测试文件。

**行为见证至少回答三个具体问题。** 原状态是否失败在题意中的行为；候选修复后同一命令是否改变；一个相邻但应保留的行为是否仍成立。第三项按issue决定，不机械增加。开发材料里可以用公开真实修复检查见证的区分力，但该修复只用于离线结果标注，不能进入部署输入。线上没有gold patch，只能报告当前证据的范围，不能把fail→pass视为充分正确性证明。若判据自身改变，旧“通过”不沿用。

**模型时间分成两次明确的问题。** 第一部分在同一模型/同一Agent/同一剩余时间下比较原样继续和一次短反馈；只改变反馈内容，别同时换schema、模型、输出预算。可以在几个新的已暴露开发状态进行有/无反馈的成对续跑；其结果只说明局部恢复，不替代从issue起点的整题成功。第二部分才验证12B真实容量与adapter迁移：真实输入/监督token数、前向/反向/Adam、训练峰值、实际监督吞吐，然后同CT版本base/adapter闭环。先容纳一个真实样本，再决定小批训练，不用16K配置上限假装已测容量。

**预算保留给结果能改变决定的对照。** 周量级内应只保留一个机制候选和一个训练候选，预留约三分之一实测额度用于独立issue的base/adapter或机制对照。其余才用于模型加载、真实训练首步和小SFT；首步若OOM或导出不能在CT起效，就停留在该问题，不继续扫描多窗口、多rank、四模型组合。具体小时数由主实验在实测速度和当前配额后确定，不能由论文的H100成本换算L4承诺。

**明确放弃本阶段的“自生成验证器＋大规模RL”方向。** 当弱复现仍能把ForwardRef或空修复判成成功时，用这种奖励做RL会优化错误目标；先把证据—动作—结果的样本质量做实。保留小规模SFT作为可检验假设：它至少必须在官方CT上改善真实动作或整题修复，并记录伤害案例。低训练loss、更多合法工具调用、更多技能和更高流程合规分，都不能单独证明接近金牌。

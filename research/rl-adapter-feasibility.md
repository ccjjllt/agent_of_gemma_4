# 当前 GRPO 方案

更新：2026-10-30。目标：用比赛129道公开任务训练独立 LoRA，挂载官方 W4A16 CT 基座。双A800已完成BF16基座与LoRA加载，并产生真实工具调用；完整题组、GRPO更新和CT效果仍待实测。

## 模型与更新

| 项目 | 配置 |
| --- | --- |
| 硬件 / 基座 | AutoDL A800 80GB × 2；对应 QAT 未量化31B，BF16冻结基座 |
| 训练后端 | Unsloth跨卡分层；TRL 1.15 `GRPOTrainer`负责裁剪目标、KL和优化器生命周期 |
| Adapter | r32 / alpha64 / dropout0；400个文本投影，暂排除共享K/V映射待验证的10个full层 `k_proj` |
| 上下文 | 每次实际模型调用总窗口32,768；保留完整任务轨迹、官方上下文管理和完整验收 |
| 采样 / 复用 | 每题8条完整轨迹，每批目标4题；同批最多更新2次，之后重新采样 |
| GRPO目标 | 概率比裁剪0.2/0.28，固定初始reference、KL系数0.01；固定长度归一 |
| 优势 | 各题组内中心化并按标准差归一，分母下限0.05，避免放大小幅效率奖励 |
| 数据 / 交付 | 服务器手动获取官方原始资产；导出独立PEFT adapter |

每次调用保存真实输入、生成token和行为概率；更新前固定旧learner与reference概率，复用期间不刷新。仅生成token计损失，按真实前缀逐调用反向；行为与learner的概率差用上限2的固定重要性权重修正。优化器和学习率调度跨批保留，旧策略KL超过0.05时停止该批剩余复用，不影响完整验收。

## 复合奖励

`R = 1×完整修复 + 0.3×FAIL_TO_PASS修复率 − 0.5×PASS_TO_PASS回归率 − 0.02×成功轨迹token成本`

分项来自同一次完整官方验收的JUnit报告，仅裁判侧读取测试信息；效率项在成功后计算且有上限，不提前截断轨迹。成功奖励始终高于失败最高分。组内任一候选缺少可靠分项证据时，全组停用测试分项，保留终局和成功效率奖励，避免缺失统计带来虚假优势。基础设施或无法归因的验收失败不伪装成零奖励。

## 动态采题与筛组

- 先覆盖未访题，再结合奖励方差、中等成功率和访问次数调整采样优先级；保留20%均匀探索，并降低同批重复仓库的优先级。
- 每组8条全部完成后才判断奖励方差；低于阈值的组保留真实结果并让新题补位。
- 每批最多尝试12组，不反复重采同一题；不足4个有效组时按实际组数更新，没有有效组则不更新。
- 记录实际选题概率、全部候选与入选组的成功率。自适应采样和筛组改变了训练分布，不把入选组成绩当成129题均匀评估成绩。

## 执行边界与入口

题面、`base_commit`和官方资产保持原样，参考补丁与验收资产仅供裁判侧；排除列表中的题不进入采样器。工具与验收使用独立CPU进程及低权限UID。当前GPU生成仍串行，连续批处理和跨工具KV复用尚未实现。

首批先取1个有效题组、每题仍采8条完整轨迹，最多尝试3题；同批最多更新2次，总进程上限2小时。正式配置仍为每批4组、最多32批。会话预算显式设为60分钟、100次工具调用、50回合，命令与验收超时各300秒；原版示例的1分钟/10次工具预算仅在运行配置中覆盖。

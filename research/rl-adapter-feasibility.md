# 当前 GRPO 研究方案

更新：2026-10-30。目标是用比赛129道公开任务训练独立 LoRA，挂载官方 W4A16 CT 基座。当前已实现训练链路，31B 完整题组、GPU 更新与 CT 收益尚未证实。

## 核心方案

| 项目 | 当前配置 |
| --- | --- |
| 基座 / 后端 | 对应 QAT 未量化31B，BF16冻结基座；Unsloth双A800分层，TRL 1.15 GRPO |
| LoRA | r128 / alpha256 / dropout0；400个文本投影，暂排除10个共享K/V的 full层 k_proj |
| 上下文 / 采样 | 每次调用32K；temperature=1、top_p=1、top_k=0；保留完整轨迹与官方验收 |
| 题组 / 更新 | 每题8条完整轨迹，每批目标4个有效题组；同批最多更新2次 |
| GRPO | 比率裁剪0.8～1.28，初始基座reference，KL系数0.01；优势归一分母下限0.05 |

old概率从首次完整梯度前向冻结，复用期间不刷新；reference可精确缓存或在零LoRA等价时共享评分。仅生成token计损失，完整前缀参与反向，不detach前缀KV。旧策略漂移超过0.05时停止剩余复用；Adam与调度器状态跨批保留，不跨策略批次回放旧轨迹。

rank 128 对应约9.70亿个可训练参数，为原rank 32的4倍；alpha/r仍为2，但不保证相同更新幅度或更高收益，`target_kl`也不是首步更新的严格上界。基座按BF16加载；若LoRA参数、梯度及两份Adam矩为FP32，这部分合计约14.45 GiB，尚未计入基座、KV和激活。实际dtype与字节量写入`policy_parameter_precision`，双卡峰值需实测。独立adapter导出为BF16，纯权重约1.81 GiB，完整续跑状态保留训练精度；CT挂载及评分效果仍未验证。

## 奖励与采题

`R = 完整修复 + 0.3×修复率 − 0.5×回归率 − 0.02×成功轨迹token成本`

分项来自同一次完整官方JUnit验收，效率项仅在成功后计入。缺失分项保留未知值及区间，不填零；完整观测用组内标准化优势，缺失时保留可证明方向的区间信号，必要时回退到全组共同可靠分项的缩减目标。基础设施故障不作为模型零分。

- 选题按20%全局均匀探索、30%未访覆盖、50%近期反馈分配；同批不重复，首批反馈可从第二批影响复访。
- 当前策略无可用信号的题暂退出自适应池，仍保留均匀复查；实际策略更新后解除抑制。
- 完整8条结束后才筛组，每批最多尝试12组；不足4个有效组按实际数量更新，全无信号则不更新。
- 保存全部完整候选的奖励、缺失原因、优势和选择概率。后验筛组不能追回采样成本，自适应分布与缺失回退仍可能带来偏置。

## 执行边界与证据

官方数据只在服务器直接挂载，题面、base_commit及资产保持原样；参考补丁和验收资产仅供裁判侧，不读heldout。训练集成绩不称独立泛化结果。

生成使用4槽连续批处理、分块与共享prefill、KV容量扩展和异步持久化，配合8个CPU worker。训练时钟默认扣除已确认的纯排队时间，并保留原墙钟；该口径不等同比赛官方墙钟评测。运行、续跑与额度见[训练说明](../training/README.md)。

| 证据 | 能支持的结论 |
| --- | --- |
| [旧GPU日志](../results/autodl/) | 串行版本11次调用共1297 tokens，约3.16 tokens/s；没有完整题组或GRPO更新证据 |

CPU 手动核对已覆盖数值、恢复、调度、BF16 导出与私密凭据；本地日志已清理。Linux 原生权限和31B GPU仍待实测，已有核对不能证明实际加速或修复收益。

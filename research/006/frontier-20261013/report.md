# 006 前沿机制与学习路线：从可调用技能转向可兑现的恢复

日期：2026-10-13，北京时间。阅读了 005 前沿与训练报告，再精读下列五项不同的一手研究；不重复 AutoCompact/SWE-MeM/CoACT。论文数字均为作者报告，未在 Gemma 复现。本轮只阅读论文、作者代码和项目已有说明，没有运行 GPU、训练、教师生成、外部数据下载或 heldout 读取，也未新增测试。

## 本轮改变研究路线的判断

1. **近期最值得试的是“错误发生时才介入”的短恢复流程。** 四题 single_state 的新增技能零调用，说明工具存在与策略触达是两件事。下一轮应直接观察真实错误之后的下一动作是否改变，而不是再增加技能和常驻规则。跨题学习经验与本题恢复先分开；正式评测不依赖从评测题积累经验。
2. **训练不再必须绕着 31B 长轨迹 OOM 排队。** 同轮官方核实已允许 12B/E4B/E2B CT，单次提交各 Agent 必须同变体，仍是 4×L4/12h。12B 值得成为独立能力—成本候选，但没有证据证明它比 31B 更强或一定容纳长序列。[官方模型公告](https://www.kaggle.com/competitions/gemma-4-developer-agent/discussion/748287)。具体官方快照由本轮官方研究分支保留。
3. **短样本要靠真实部署状态的重建，不靠删去历史后接上旧答案。** 现有 31B 只完成合成 2048 诊断，真实 6032 反向 OOM；本地 9 题、外部 7 条结构化尚未同协议。能立即推进的是来源清晰的局部状态与动作证据，不能提前许诺可用的 2K/8K 恢复集。
4. **多候选选择先验证选择能力，再支付生成成本。** 无法识别已有正确补丁时，多生成几个会同时扩大错误空间与费用。论文中的 10/16 候选和强专有裁判不是比赛五分钟配方。

## 1. Sentry：经验应按失败状态触发，常驻提醒可能起反作用

[论文 v1，2026-10-02](https://arxiv.org/html/2610.02994v1)，重点 §3–5、Tables 1/5、Appendix A.4/A.6。同一 Qwen3.5-9B 负责执行、检测、恢复与验证；SWE-bench Lite 抽取 50 个可执行题，五次运行均值从 20% 到 30%，最强运行时基线为 24%。其 200 个同状态分支干预来自四个基准，并非全部 SWE；局部恢复 33.5%→60.5%，最终结果改善/持平/变差为 74/101/25。不能忽略伤害干预。

Agent 每次最多生成 384 tokens，辅助调用最多 4096；SWE 总 token 1.06M→1.73M，平均任务耗时少 31.7 秒，但不是相同五分钟硬预算的 Gemma 对照。局部“恢复”还包括同模型判断，不等于官方修复成功。论文的人审中 SWE 恢复判断准确率为 76.9%。常驻经验劣化的控制实验主要在 WebShop/Mind2Web，不能直接断言 Gemma 也劣化。

**本项目迁移：**从确定错误开始，如缺必填参数、已明确失配后原样重复；只在发生时提供一条与错误对应的动作约束，先不用另一次 LLM 检测。对“搜索无进展/该提交了”的语义干预另做一臂，防止混入不可靠判断。恢复后的动作必须实际执行，不能用一句自我确认算成功。此流程能否接入官方消息/工具回包，须先核实允许的声明式接口；普通技能无法拦截原生调用，不能宣称已接通。

**复现资源：**[作者仓库](https://github.com/nuglifeleoji/Sentry)、[paper.yaml](https://raw.githubusercontent.com/nuglifeleoji/Sentry/main/configs/paper.yaml)可读，窗口 5、恢复观察 10、检索最多 5 条。README 同时留有“完整版本待发布”说明；本轮只确认代码目录、配置和调用示例存在，未确认完整 SWE 基准复现。无需搬整套框架。

## 2. SWE-Replay：复用已取得的证据，但必须恢复真正的执行状态

[论文 v1，2026-01-29](https://arxiv.org/html/2601.22129v1)，重点 §2.2/3.1、Table 1、Appendix A.1。mini-SWE-agent / Live-SWE-agent，Gemini 2.5/3 Pro 与 Devstral-Small-2。Verified 每题 10 候选；Gemini 最多 250 步、Devstral 128 步，不设费用上限。Devstral 的 mini 对照为 62.2%→63.2%，费用 $1.53→$1.36；Gemini 2.5 为 58.0%→60.2%。摘要“3.8% 改善”是相对值，不是 +3.8 个百分点。

方法一半概率从头探索，一半从旧步骤分支；恢复此前消息和仓库 diff，遇安装依赖等非仓库状态变化则回放动作。新动作之后重新生成后缀。最后用原仓库回归测试过滤并多数选择，没有使用生成复现测试。该设计仍依赖额外执行预算；更大 pass@K 不等于单次提交可选出的收益。

**本项目迁移：**先用已暴露开发轨迹研究“知道修法但未落地”的一个分叉点：相同仓库状态与可见消息，一臂继续，另一臂只得到简短执行提示；总新增推理预算相等、剩余时间明确。现有补丁快照可复用，不能仅凭 diff 恢复声称已恢复 pip 安装、后台进程、shell 状态。公开论文提供算法；本轮未核实到作者 SWE-Replay 代码发布，不依赖搜索到的第三方实现。

## 3. SWE-AGILE：snapshot 不等于删除旧观察，不能直接解我们的长度瓶颈

[论文 v1，2026-04-13](https://arxiv.org/html/2604.11716v1)，重点 §2.1–2.2/3.1、Appendix B；[作者代码](https://github.com/KDEGroup/SWE-AGILE)。Qwen3-8B，约 2.2K SWE-Dev 轨迹加 200 条同框架采样，SFT 后 Verified 15.83%→21.45%；再以 896 个 R2E-Gym 任务 RL 到 24.05%。SFT 26K、4 epochs；评估 64K、60 步、两次均值。这不是少量 2K 轨迹即可复现的结果。

它保留全部历史 observation/action，仅将较旧 reasoning 换成 digest，每个 snapshot 只监督当前响应；训练视野与运行时一致。其 hindsight backfill 用未来目标动作生成 reasoning，作者 [fillback.py](https://raw.githubusercontent.com/KDEGroup/SWE-AGILE/main/data_process/fillback.py)明确接收 target_action。此类合成标注不是原模型真实思考，不能补写进本项目旧轨迹再当作当时可见事实。代码当前滑窗解析器针对 Qwen，不能直接套 Gemma。

**本项目迁移：**采用“部署会看到什么，就在训练时看到什么”的原则。本项目部分ATIF明确保留thinking原文，导入器也支持reasoning_content；早期索引缺字段不代表原件全部没有。主代理本轮复核的8条v3轨迹均有非空thinking事件，但字符统计不能代替正式模板token长度。需按实际轨迹区分reasoning和工具观察的长度后，才能估算压缩空间；SWE-AGILE仍保留全部工具历史，所以不能直接宣称它能把6032-token样本变成2048。要训练短状态，必须先定义真正部署的恢复/交接入口，让其从当前源码、错误、diff组成新状态，然后从该状态实际续跑；这个新实验不能叫原完整轨迹无损缩短。

## 4. SWE-Lego：更可靠的数据监督有直接消融，但算力规模不可照搬

[论文 v1，2026-01-04](https://arxiv.org/html/2601.01426v1)，重点 §2.3/3/4、Tables 4/5 和 Figure 7。Qwen3-32B，18.1K 轨迹、128K 全参数 SFT、4 epochs；未经 refined SFT 的 48.8%，加错误屏蔽与课程到 52.6%。固定课程时去掉错误屏蔽降至 50.4%，证明成功轨迹中的坏动作不应全部学。错误动作仍留上下文；屏蔽不包括为复现 bug 而故意产生的失败。

其 rollout 消融还发现去掉低效 task_tracker 后有效轨迹率 27%→30%、平均 65.5→62.5 步，样本为 100 个外部题。不是所有规划工具都必需，也不能据此断言本项目状态技能无效。紧预算优先增加有效连续交互，100–140 步附近才出现转向并行采样的饱和，不能按该数字设 Gemma 门槛。

**本项目迁移：**保留当前正确的错误屏蔽方向，优先扩大独立 repo/issue，不靠同 9 题切片。12B 使实际训练更值得测量，但这篇论文没有提供 Gemma 12B 或 QLoRA 的收益/显存承诺。

**可获取资源：**[作者仓库，已重定向到 LegoX](https://github.com/LegoX/SWE-Lego)明确给出 `SWE-Lego/SWE-Lego-Real-Data`、`SWE-Lego/SWE-Lego-Synthetic-Data` 的 resolved split、instance_id/messages，以及 verifier 数据。它是下一候选来源，不是已入库数据。HF 数据卡本轮访问失败，未核实数据许可或下载任何轨迹；不得把仓库代码许可外推到数据。首先只取元数据，排除比赛四仓库和镜像，再抽独立来源核对工具语义和完整长度。

## 5. Agentic Rubrics：有源码依据的验收条件有用，弱自评并非免费裁判

[论文 v1，2026-01-07](https://arxiv.org/html/2601.04171v1)，重点 §3–5。500 个 Verified 题，每题 16 个 Qwen 候选；32B 最多 30 turns、Coder-30B-A3B 50 turns。Claude Sonnet 4.5 浏览仓库写 rubric、GPT-5 low 判分；Best@16 为 40.6%/54.2%，强 patch-classifier 为 37.1%/50.2%。不能把这个差额当成 Gemma 自评的增益。

固定 GPT-5 裁判，改用未训练 Qwen 写 rubric 只有约 43–45%，说明关键可能是生成标准的能力。蒸馏用了 2000 条教师 rubric 轨迹、32×H100、两 epoch；非本轮轻量方案。其低评分但测试通过案例中，46% 判断被分析为过度限定/冗余/冲突等低效标准；该分析自身也是 GPT-5 辅助，不是绝对真值。

**本项目迁移：**先人工从 issue 与已读源码写 2–4 条可被观察反驳的行为约束，例如“回调恢复且原 lifespan 仍保留”；不用 checklist 的条数代替证据。先拿已有不同补丁做盲选分析，看看这些条件能否排掉错补丁而保留正确者，再考虑额外生成。后续如在线运行，生成与选择必须使用同一获准 Gemma 变体并共同计入预算。本轮仅确认[作者项目页](https://labs.scale.com/papers/agenticrubrics)与论文附录提示公开，未核实可下载训练数据/完整代码。

## 短状态训练的因果边界与具体材料

下面是本项目新设计，不是上述论文已证明的结论。

**A. 保留原始完整历史作为来源，但训练输入使用一个明确的新子任务。** 子任务示例是“从当前文件状态恢复这次实际失败的编辑”，不是“假装从 issue 起点已经走到这一步”。输入只含触发时已经存在的目标、工具 schema、实际失败调用/回包、工具重新读取的源码、当时 diff 和剩余约束。后来的正确补丁、判分、目标动作不能进入 state builder；若缺少决定动作的依据，就补读或丢弃该样本，不能补编。

**B. 转协议后必须重新执行动作。** 外部 `str_replace_editor` 失败不保证官方 `edit_file` 也失败；源 `bash` 与官方 subprocess 的状态/反馈格式不同。同一外部前缀可以成为任务来源，但不能捏造“官方曾返回同样错误”。从固定 base commit 重建当前修改，执行官方动作产生真实观察；有后续替代动作则从同一状态分别执行。未经执行的候选只记提议。

**C. 局部成功与整题成功分层。** 参数合法、旧串匹配、一次编辑完成仅是局部结果；不继承整条轨迹的 resolved=true。失败动作 loss=-100，真实有效恢复才作目标；多个 snapshot 仍是一个 issue。选择集按 repo/issue 分组。所有上下文长度都经过部署模板/tool schema 后计数，不能先承诺 2048。

**D. 先拿已有 7 条结构化来源做一份人工实例，不立刻扩建转换器。** 优先一个匹配失败链，写出当时可见信息、当前文件状态来源、源协议/官方协议差异、恢复动作证据与实际编码长度。若无法恢复，就换另一条，不截尾凑短。候选自然全对话 ≤8K 的 click 可另作完整任务来源，两者不要混称同一种训练目标。

## 最小研究顺序与判断依据

| 优先级 | 先交付什么 | 后续有限模型实验 | 会改变决定的真实结果 |
|---|---|---|---|
| 1 | CPU 从旧开发轨迹定位参数错误、重复调用、已确认行为后拖延的具体分叉点 | 复用一次 CT 加载，固定同一模型/提示，仅比较是否收到触发式短反馈；每个原始状态算一个样本 | 原本失败动作是否被替换、是否落地生产编辑、整题修复是否增加；同时保留负干预 |
| 2 | 12B 官方 CT/未量化来源与加载接口清单；相同 Agent 配置 | 先 31B base 对 12B base，同题同墙钟；再测 12B 一个真实样本前反向/Adam，不做窗口扫描 | 真实修复、工具错误、端到端时间、训练峰值与监督吞吐；不能只看 tokens/s |
| 3 | 一个状态重建实例与一个完整短任务实例，保持来源/协议差异可查 | 数据与容量足够后才做 12B 小 SFT；12B base 对 12B adapter 同预算 | 完整真实交易能训练，正式 CT 上局部与整题收益；31B→12B与训练作用分别归因 |
| 4 | 已有候选补丁的盲选材料，条件只由 issue/可见源码制定 | 只有证明选择能保留正确候选后，才做最多一次分支；总预算与单路径相等 | 选中正确补丁净收益是否抵得过分支/判断的时间，不报 oracle pass@K 当实际成绩 |

这些都不是本轮已运行的实验。12B 先得到公平修复/吞吐和真实训练容量证据，比继续仅攻 31B 的 16K 容量更能改变路线；31B 基线仍保留。E4B/E2B 暂不与所有机制做组合搜索。即使更小模型更快，也可能错误更多；若它腾出的时间不能转换成更多正确修复，仍应选 31B。正式 submission 的 0.13 由用户本轮确认，单一总分没有 per-task 轨迹，不能反向证明上述任一失败机制。

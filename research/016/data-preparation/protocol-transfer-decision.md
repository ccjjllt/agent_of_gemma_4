## 原生语义路线可以保留什么

在使用正确的**来源工具定义**时，原问题、实际源码观察、定位推理、原生工具参数、真实错误/检查反馈、读反馈后修复的动作顺序可以保留；成功证据仍注明来自作者执行，不声称已在比赛环境重跑。无损解析XML/JSON到Gemma消息和函数调用边界，属于序列化适配，不需要为每条轨迹重新执行所有命令。

对应的来源工具观察仍是来源观察：例如原编辑返回带行号的改后片段，不能宣称是比赛编辑器返回的JSON/diff。来源原生submit/finish按来源终局表达，不伪造比赛submit_patch响应。源工具中的think若被保留，就在该来源协议下保留其实际工具语义；将其并入Gemma reasoning channel是另一项有历史边界影响的转换，不能静默删除think及其回包后拼旧未来。

模型学习的是“依据观察定位、修改、验证与恢复”及代码能力，实际迁移效果尚未得到本项目实证。原生语料里的网络安装、无限追加检查、来源专用结束行为可能给比赛带来负迁移，因此应筛选/屏蔽明显无效目标，保留必要因果上下文，并尽早观察目标协议行为。

当前 `load_encoded_jsonl` 要求一个数据版本具有同一tool/protocol指纹。**第一步不扩大为任意多schema训练框架。** 将Smith两种表示归一到同一三工具定义；Lego若随后确有高价值可用量，再作为明确的后续来源阶段。最后六工具适配是新数据/协议阶段：从主训练adapter继续，使用新的优化器/调度预算并记录来源；这不是旧checkpoint的同配置恢复，不能绕过FSDP resume的数据签名检查。需要一个明确的adapter warm-start入口，不能仅改 `--resume` 的配置。

## 哪些映射不能只改名字

| 来源操作 | 六工具中可能对应的操作 | 必须解决的差异 |
|---|---|---|
| `bash` / `execute_bash` | `run_command` | cwd、shell/session环境、软超时/`is_input`、网络/依赖、退出码及输出截断；执行命令字符串相同不代表观察相同 |
| editor `view` 文件 | `read_file` 或命令读取 | 绝对/相对路径、行范围、目录与文件区别、head/tail缩略及默认150行；不能保留目标不可能返回的源码 |
| editor `view` 目录 | `run_command` 的目录查询 | 不能转换成read_file；新命令必须实际产生所用的目录观察 |
| editor `str_replace` | `edit_file` | `path/old_str/new_str` 到 `filepath/old_string/new_string`；当前文件内容、唯一匹配、空白匹配策略、失败反馈与编辑后观察均需核对 |
| editor `create` | `write_file` | 来源create拒绝已有文件，目标可以覆盖；仅在已证实目标不存在时才有等价写入条件 |
| editor `insert` / `undo_edit` | 多个普通读/改动作 | 行号及原编辑栈无法凭函数名还原；缺状态时首版排除对应转换类别 |
| `submit` / `finish(message)` | `submit_patch` 与普通终局 | 来源首次submit可能注入复查清单，finish可能只是结束且含正文；捕获diff、反馈和回合结束必须分开处理 |
| 原生think / 来源不存在的budget查询 | Gemma思考或 `get_status` | 不是可默认替换的环境工具；不要为凑齐六工具伪造状态、预算或执行回包 |

目标语义依据现有实际wire schema：`research/015/data/on-policy-rft-first-v1/actual-tools.json`。旧官方工具实现摘录可供定位，正式重放必须使用当前冻结比赛实现，不能只据旧版本描述推断运行效果。

## 最少需要的真实六工具证据

**不是全库逐题重跑，也不是零重放就宣称迁移完成。** 先复用P015已保存的目标协议真实train请求与观察；编码器修正终局、长度允许后，优先恢复完整有效链，而不是继续只取14条短动作。

随后按实际发生的映射类别，取得最少的一条完整“当前状态→目标调用→真实返回→消费该返回的后续动作”记录，覆盖：

1. 文件读取范围/截断、目录读取与cwd；不能只核对函数参数解析成功。
2. 唯一编辑成功、匹配失败后重读恢复、create的不存在条件；比较实际文件状态和工具反馈。如果目标工具在原失败处成功，停止直接拼接原未来，保留局部证据或另做真实续行。
3. 原有修前失败/修后通过命令在目标环境中的执行、实际非空diff捕获和正确结束。没有执行的判据不填成功；来源新增测试、参考patch和未来裁判信息不能交给生成模型。

选择**3–5个已有环境较容易复用的train问题**取得完整六工具链，优先包含一次恢复、一次不同目录/相对路径和一次正常验证后结束。这是尽早识别系统性转换错误的最小启动集合，**不是说3–5题足以完成协议训练，更不证明其他转换样本都正确**。使用来源已有F2P/P2P与项目既有执行材料，避免建设专用测试项目。实际适配语料应按有效目标token和行为覆盖扩量，不能反复复制这几题。

凡最终被标为六工具训练数据的样本，都需要本样本的状态/观察语义依据；只有抽样重放的转换规则，不足以替其余被改变语义的回包背书。无法可靠迁移的部分继续留在原生语义池，或者只标局部动作证据。

## 可执行的优先级

**现在先做：** 固定Smith原生三工具定义与Gemma序列化，编码当前诊断≤32K的完整候选，人工核对失败恢复和终局边界，再扩大同类来源的冻结train身份。不要把当前profile文件直接送入trainer；它没有可训练labels，也仍挂着错误的六工具语义说明。

**同时准备：** 从P015现成目标协议train记录恢复完整链，按上述类别限量补真正六工具重放；补“新阶段从指定adapter初始化”的明确入口，使主SFT→短适配能够实际执行。保持正式推理Agent不变。

**GPU到位后采用一条主配方：** 原生主SFT早期预定checkpoint先确认没有严重目标工具格式/重复行为退化；按已准备的真实六工具语料做明确短阶段，再做固定Agent的同期base/adapter修复比较。若来源协议行为持续侵入目标六工具、或适配仍只有几个短read/edit，先修适配数据，不机械把全部大训练预算跑完。

**暂缓：** Lego Real全量六工具重放、OpenHands终端/undo完整仿真、任意多协议训练框架，以及为了跨工具迁移先自采整库轨迹。Lego现有短样本仅在能增加真实验证/恢复覆盖且适配成本合理时补入；长尾不会因保留原生工具就自动缩短。

# P012 handoff_v1：候选交接与最终提交职责（冻结 v1）

日期：2026-10-19。对应交接文档 §2 末段与 §3。

## 1. 工具持有

- 修复 A/B、定位、验收：五工具 `run_command/read_file/edit_file/write_file/get_status`，
  无 `submit_patch`。见 `repair_tools_v1.json`（`five_tools_sha256 91ec82b1…`）。
- 最终选择器（base）：六工具（含 `submit_patch`），唯一可调用提交的角色。
  选择器先恢复选中快照，再调用一次 `submit_patch`。

## 2. 候选绑定

- 每个候选的 patch 快照、源码指纹、命令结果、验收结论绑定同一 `candidate_id`（`A`/`B`）。
- 禁止验收 B 却提交 A 的工作树；B 从最初 baseline 恢复，不在 A 补丁上继续改后冒充独立路线。
- `patch_store` 最多 4 快照、8 文件、单文件 200KiB/合计 512KiB（含未跟踪文件）；
  HEAD 变化时恢复按实际失败处理，不静默删文件或放宽规则。
  （实现现状：`patch_store.py:52-56,315-318` HEAD 变化直接 fail；文档注释称 warn 但实现为硬拒，
  以实现为准。）
- `working_state` 现只有单份 `state.json/handoff.json`，需按候选和阶段区分运行记录，
  否则下一角色覆盖上一候选证据。P012 新增 `candidate_id + stage` 命名空间，不另建测试平台。

## 3. 验收纪律

- 验收者输入：原问题、实际 diff、执行证据；不看修复者自信结论。
- 检查：需求主体是否实现、是否只加导入/测试脚本、是否误改接口、
  已有检查和一次性复现是否运行了修改后的真实源码（`PYTHONPATH=src:.` 类修正保留在研究载体，
  不进入正式包）。
- 验收不得修改生产源码；临时验证产物放临时目录；记录验收前后 diff。
- 验收结论只写证据与是否通过，不写“最佳”判断；选择错误率需等所有生成候选完成事后裁判
  才能计算，缺失裁判时写可判定分母与未知数。

## 4. 提交语义

- 官方 `submit_patch` 捕获当前工作树、整题停止、可多次调用、未调用则兜底抓 `git diff`
  （`agent_runner.py:854-864,1048-1103`）。P012 在线流程要求：只有选择器调用它；
  修复/验收角色 prompt 与工具清单均不含它，避免误调。
- 最终提交前预留约 45 秒及必要调用，用于选择、恢复与提交。
- 事后裁判在独立副本运行，不反馈给在线选择器，不计入在线耗时。

## 5. 预算

- 四组统一 8 分钟 / 28 调用；定位约 1 分钟；优先完成 A 及验收；仅在剩余预算可容纳
  另一完整尝试时进入 B。阶段时间是调度策略，不是每角色硬限。
- 采样与上下文沿 P010：temperature 0.2、top_p 0.95、thinking 1024、单次 max_output 4096、
  32768 上下文。各角色可见历史由架构改变；内部摘要请求未必继承总输出上限，需显式处理，
  不得把子角色消耗藏到预算之外。

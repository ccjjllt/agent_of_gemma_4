**7．结果应支持决策，记录复用现有原始输出。**

每题保留issue身份、arm、adapter及Agent版本、顺序/seed/并发、实际路由、F2P/P2P结果与覆盖、patch、提交状态、超时和环境异常。优先从现有`raw-wire`、`raw-model`、ADK事件、trace、`context_metrics`和判分日志离线提取以下诊断，不另建评测框架。

| 证据 | 解释边界 |
|---|---|
| 来源工具名、参数/schema错误及重复失败 | 每题出现与每次调用分别统计；没有解析错误仍可能有观察语义迁移问题 |
| 首个实际生产源码变化的秒数/轮次 | 工具返回成功不等于已有有效修改；不把纯读、空替换或临时脚本当源码修复 |
| 编辑→验证→反馈→再编辑→复查 | 区分最终代码版本是否验证；编译通过不等于行为通过 |
| 实际输入token、压缩事件、reasoning/action输出token | 用请求与固定tokenizer，不把字符数当token；关联不等于长历史导致失败 |
| 模型API区间、生成量、可用服务计时 | 分开模型生成与共享服务等待；如缺TTFT/prefill分解就标不可分解 |
| 最终diff、提交、超时、F2P/P2P | 超时且回收patch通过可以同时成立；不要用单一状态覆盖另一事实 |

主表报告 `W=LoRA独胜`、`L=Base独胜`、`W−L`、`(W−L)/N_valid`，另列共同成功/失败、计划N、完成N、无效及缺失原因。P2P缺失写“未覆盖”，不能写“回归通过”：现judge允许`p2p_pass=null`时F2P通过仍记resolved。主结论优先使用F2P/P2P均有明确证据的预定面板；覆盖不足题单列，保留原始判定。

模型补丁导致的import/collection错误是真实修复失败，不可当环境故障剔除。只有与模型无关且有clean/reference证据支持的基础设施错误才单列无效；同一题一臂缺失时保留整对状态，按预定规则完整补跑，不只保留最好结果。正常会话超时计入有效结果，除非强杀造成patch/判据不可恢复。

同时报告配对差的不确定性，例如按配对任务bootstrap区间，并按仓库列W/L；仓库数很少时区间仅描述当前样本，不宣称覆盖整个隐藏分布。1–2题差异称方向性证据；对预定的争议对复跑，两臂使用相同seed清单、保留所有结果，不使用best-of。优先人工读回退题、LoRA独有异常和共同失败主类；成功轨迹只抽查必要对照。

| coordinator的作业接纳 | 剩余时间不足以完成整对Agent＋judge＋清理时停止接纳新题对；现150秒接纳/60秒前强杀不适合大面板 | 保存已发生结果、剩余任务及原因，不新堆blocked/skipped文件 |
| [attempt_worker.py](../../research/015/inference/attempt_worker.py)及离线汇总 | 复用现raw日志，补上述统计和回归覆盖说明，避免改Agent执行语义 | 当前工具、提示、历史压缩及F2P/P2P判定来源 |
| 条件性Step-30输入 | 读取checkpoint自身完整manifest、step和adapter SHA，产生诚实的评测物料记录 | 不篡改最终manifest冒充training_completed，不要求加载optimizer |

以上是**待实现清单，不是本次已完成代码**。当前builder只接受3600/4800秒等旧上限，原配额14h计划也属于旧会话；不能换selection就直接运行。人工核对生成包只改变指定变量、成员与SHA准确；复用一次性Shell/Python检查，不增加测试套件。

Agent预算满额时的串行合计：D的24次×5分钟为2小时；C的48–64次为4–5小时20分钟；合计6–7小时20分钟，不是实际耗时预测，也不包含服务启动、准备、判分、复跑和清理。D四并发的理想Agent部分约30分钟，但实际受GPU共享影响。L4配额按当前2倍页面规则另算，启动前读取账户真实余额并确定本轮授权上限。不能简单把4×卡数、平台配额倍数和墙钟混乘。材料按完整题对分片，优先留足C及正式候选验证预算；不自动租卡或消费旧授权。

**9．哪些研究值得转成下一轮动作。**

外部结果均是其他模型/框架/预算下的证据，不是本比赛预期分数；本节仅保留能改变具体决策的六组资料。

| 一手来源 | 可迁移的结论 | 本项目动作与边界 |
|---|---|---|
| [SWE-smith论文](https://arxiv.org/abs/2504.21798)、[官方训练流程](https://swesmith.com/guides/train_swe_agent/) | 大规模多仓合成任务和执行验证后的专家轨迹能支持SWE能力训练 | 保留高质量变异任务；按独立问题、仓库和行为覆盖扩量，不能用重复六题替代规模 |
| [SWE-Lego §3.1](https://arxiv.org/html/2601.01426v2) | 保留完整失败上下文、屏蔽明确错误assistant动作的loss，同时保留正常复现/测试失败监督 | 本地已mask来源turn_mask和部分editor错误，先检查剩余错误类别；不要重复宣称从零新增此机制，也不删除所有失败轨迹 |
| [Open-SWE-Traces §4](https://arxiv.org/html/2606.16038v1)、[官方数据卡](https://huggingface.co/datasets/nvidia/Open-SWE-Traces) | 跨harness能迁移但会有损失；质量筛选后的未解决轨迹也可能有价值 | 可补真实PR和恢复数据；先解决目标协议产率，固定revision/教师/许可及git-hacking过滤。轨迹数不是独立题数；本地当前仅44个候选身份、0正文，不能写成已可训练 |
| [LEGO-RL](https://arxiv.org/html/2608.17393v1)、[官方实现](https://github.com/LegoX/Lego-RL) | 原生执行框架、真实生成token和压缩状态一致性影响训练 | 先借鉴目标六工具采样与真实wire保留；当前不建设在线RL生产线 |
| [The Complexity Trap](https://arxiv.org/abs/2508.21433) | 简单旧观察遮蔽可成为复杂摘要的有效比较基线 | 输入长度/摘要成本确为瓶颈后，单独比较历史策略；token成本降低不等于L4秒数同比降低 |
| [Harness Design实证研究，2026-09](https://arxiv.org/abs/2609.20804) | 上下文管理价值取决于预算，工具空间价值取决于模型bash能力 | 不预设六工具永远最优，也不预设bash-only更好；P017后固定权重只改一个有证据的推理变量 |

**10．按观察决定下一笔投入，避免同时改变所有变量。**

| 观察 | 先排查 | 下一项有界工作 |
|---|---|---|
| 来源工具名、编辑参数、终止行为出错 | schema、模板、观察和提交语义，区分解析失败与恢复失败 | 64–128个独立train问题的目标六工具完整/可解释阶段轨迹作为首批目标；规模是项目建议，不是最优配方。达不到就报告产率，不复制六题凑数 |
| 调用正常，但真实需求修不完整 | 漏掉接口、调用方、注册点、跨文件/边界条件 | 优先补真实PR和对应缺陷类型，保留有价值变异；不机械规定七三比例 |
| 编辑后无验证或不根据反馈纠正 | 是否会调用有效上游检查、是否验证最终代码 | 补真实失败反馈→理解→修改→复查→结束；普通final边界必须来自真实生成，不能伪造 |
| 输出变长/首编更晚/超时多 | reasoning/action量、prefill/排队、LoRA实际吞吐 | 先固定胜出或保留权重，单独比较4096→1024 thinking；如无token证据，不先删thought或增加时间 |
| 只有长历史/压缩后退化 | 输入长度、任务复杂度、压缩丢失信息是否同时变化 | 优先20K–25K代表性完整题或真实压缩后状态；25K单次更新成功不保证整桶安全，不回到32K容量攻坚 |
| Step-30稳定优于68 | 同期复跑、数据顺序、loss和任务覆盖 | 选较早checkpoint或降低后续更新强度，一次改变一种因素，不直接宣布过拟合 |
| 两臂几乎相同 | SHA/路由/模块注入、标签/模板、NF4→CT | 少量非评估诊断输入及必要数值迁移比较；排除这些后再考虑数据量或rank，不同时增加rank与epoch |
| W明显多于L，确认题方向保持 | 回退集中度、P2P、串行耗时 | 固定候选，准备一次正式提交；扩高质量独立任务，不重做Agent框架 |

六工具适配不应仅把工具改名。现种子虽声明六工具，正向动作只覆盖四种工具，且一题占68.84%监督；无需为了凑齐工具种类伪造无意义调用。优先取得不同问题上的可靠定位、编辑恢复、有效检查和提交行为。转换改变read范围、cwd、持久shell或submit反馈时，必须实际重放受影响步骤；无法恢复状态的材料暂存，不能补写成功回包。使用已有环境、公开许可教师或Gemma在train题的真实采样，不要求重采全量公开轨迹。

新阶段从选定adapter使用`--init-run`，显式重置优化器/调度器/进度并冻结新数据，不能以`--resume`偷换协议。r8/alpha16仍作初始容量，不同时调rank、LR、epochs和thought监督。可先用较保守LR（如1e-5）的一次短适配作为候选，但这是待实测配方；训练量按独立问题与监督token报告，不按切片数报告。适配后比较“适配前／适配后”；原Base保留锚点，是否扩矩阵依据实际预算。

**11．争取更高分的路线：权重收益与运行效率分开验证，再组合。**

本项目已在失败题看到大量API区间等待，最快的额外机会可能是让模型更早形成正确补丁，而非立即扩大训练规模。P017之后按主要瓶颈选一个变量：thinking预算、定位/编辑提示、或历史管理。第一候选优先考虑现已有机制的4096→1024 thinking对照；若主要问题是输入历史或摘要失真，再换成历史策略对照。不能预设短思考必然更好。

固定同一权重比较旧runtime与新runtime；如果需要同时判断权重与runtime的交互，使用明确的2×2小矩阵（Base/SFT × 原/新runtime）并单列预算。绝不把“SFT＋新提示＋新预算”比“Base＋旧设置”的全部增量归给训练。以首次实质编辑、验证纠正和最终修复数判断收益，工具错误下降本身不是得分。推理改动必须能通过官方支持的配置、工具或扩展表达；仅在本地coordinator有效而无法进入正式submission的历史处理，不列为可部署提分方案。

外部TTS多采样/verifier、并行多Agent和在线RL暂后置：它们要消耗额外生成与判别预算，而本项目当前连本轮adapter净收益都未知。若后续证据显示错误高度可由一次验证反馈修正，可先做同一Agent内的一次有界纠正；若模型连正确候选都难以生成，才优先继续扩大高质量训练。参考修复和host私有判据只能作外部评价，不能作为Agent的候选选择器。

正式候选沿用官方CT基座与独立PEFT adapter，按官方`adapter`字段打包。开发host的F2P/P2P、诊断器和参考答案不进入submission。确认串行预算可承受后，在明确授权下提交一次，记录提交ID、完整回执与分数；保留0.15基线资产。公榜提高仅说明该次公开隐藏子集结果，不能替代私榜泛化保证。

**12．执行顺序与交付物。**

| 顺序 | 工作 | 交付与结束条件 |
|---|---|---|
| 先做CPU准备 | 提取真实最终三文件；适配旧builder/面板参数；冻结确认题身份，准备来源既有判据 | 可审阅的P017输入清单、运行协议、材料与预算估计；不先建新框架 |
| 一个连贯评测阶段 | 作业启动时完成加载/路由，再跑D；独立CPU并行准备C环境 | 真实D完整配对、必要失败诊断；系统性加载/工具错误先修 |
| 随后确认 | 按预冻C完成同期A/B，优先串行；必要时条件性step30诊断 | W/L、配对差、覆盖范围、所有失败、实际耗时/配额；给出当前应保留的权重 |
| 一次针对性改进 | 按主要失分选目标协议适配、数据扩量或推理效率中的一项 | 新数据/配置来源与独立比较；不同时扫描多条路线 |
| 候选部署 | 正式配置与预算核对、授权提交、收回结果 | 新正式回执；无提分也保留负结果用于下一轮 |

加载接入和路由核对只是主评测开头的一小段；确认材料可与D并行准备，独立train的后续数据整理也可并行。若环境供给成为瓶颈，缩小并明确确认范围，不继续堆叠状态文件。GPU、租卡和正式提交按执行会话授权与预算进行；本文不是新的消费授权。

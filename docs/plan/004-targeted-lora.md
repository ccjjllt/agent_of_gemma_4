## 研究背景与目标

本轮承接 [001：无 LoRA 基线](001-baseline.md)，从真实失败轨迹中选择一个可学习的行为开展 SFT。
可选目标包括有效工具调用、依据已读源码生成局部编辑、识别重复无效搜索；第一轮只选一个。
目标选择必须引用 001 的具体案例和出现频率，不能先决定“微调所有编程能力”再寻找数据。
沿用 [002：代码定位](002-code-localization.md) 与 [003：上下文和预算](003-budget-and-context.md) 中已经确定的策略版本。
本计划仅规定后续实现与研究安排，当前没有训练产物、兼容性实测或效果结论。

## 研究假设

- 少量与实际工具协议一致的高质量示例，可能降低某类高频行为错误。
- 局部行为改善只有转化为同预算下更多有效修复，才构成比赛收益。
- 数据中工具格式或量化基座不匹配，可能使训练损失下降而实际 Agent 表现变差。
- 仅训练成功补丁文本可能忽略搜索、阅读和执行反馈，应保留目标行为所需的交互上下文。

## 已核实的模型与资源边界

比赛全部 Agent 使用 `gemma-4-31b-it-qat-w4a16-ct`，本轮对齐已取得的官方模型版本 2。
提交保存独立 PEFT LoRA 目录，包含 `adapter_config.json` 和 `adapter_model.safetensors`。
`agent.yaml` 的 `adapter` 引用 `adapters/` 下的名称；首轮只使用一个 adapter。
官方服务支持最多 8 个 LoRA、最大 rank 128，解压后的整个提交必须小于 3 GiB。
上述数量与 rank 是上限，不是首轮推荐规模；大小必须测量实际导出文件，不能只依赖估算。
官方4×L4是评分环境，001已在4×L4上完成推理运行；这不证明同一配置足以微调。账号此前显示每周30小时额度，001记录累计使用3858秒，后续训练前重新读取当前剩余额度。
M5 32GB 可用于资料整理、数据筛选和轨迹分析；不预设它能复现 CUDA 训练与比赛推理。
训练显存取决于基座格式、序列长度、目标层、优化器及批量，不能由量化权重大小直接推算。

## 前序输入与研究范围

- 001 的固定模型、运行配置、任务划分、完整轨迹及失败分类。
- 一种目标行为的正例、反例、相关工具反馈，以及判定该行为是否正确的人工标准。
- 官方 Harness 版本、模型版本与文件标识，训练框架和推理框架的实际版本。
- 129 个公开任务的仓库分布为 fastapi 67、rich 48、requests 13、httpx 1。
- 这些任务对应 127 个 `(repo, base_commit)` 组合，任务数量不等于独立代码快照数量。

沿用 001 的划分，同一 `(repo, base_commit)` 的任务不得跨训练集与保留集。
同一任务的多条轨迹、不同采样结果和重复片段必须留在同一划分；另检查近重复问题和补丁。
若 001 已用某题调整提示词或定位策略，该题不能再作为未参与选择的最终保留任务。
按仓库报告结果；httpx 只有 1 题，不能据此声称具备该仓库的普遍修复能力。
数据不足时优先缩小研究问题，不通过挪用保留任务扩大训练集。

本轮具体清单约定：尚未用于策略选择的dev_future及其未暴露组为训练候选；dev_panel和003新增探索题用于选择与诊断，不再同时充当独立训练效果评估。训练清单、选择清单和最终保留清单按任务、同commit组及已发现近重复组互斥，003从future抽出的题须登记暴露后移出首批训练候选。heldout不参与训练、样本筛选或目标行为标注；若先前已经根据其结果选择方向，后续只能称已暴露评估，不能重新获得独立性。

## 项目自定义数据字段

以下是待实现的研究样本约定，不是官方任务、轨迹或提交 schema。

| 字段 | 含义与约束 |
| --- | --- |
| `sample_id`、`source_instance_id` | 样本标识与原任务标识，支持回查完整轨迹 |
| `repo`、`base_commit`、`split` | 仓库、初始版本及固定的数据划分 |
| `behavior_target` | 本轮唯一目标，例如 `focused_edit`；名称由研究确定 |
| `messages` | 按真实顺序保存用户、模型、工具消息，保留工具名与关联标识 |
| `supervised_spans` | 需要计算训练损失的模型输出片段，其余内容只提供上下文 |
| `source_trace`、`source_steps` | 原始轨迹位置与步骤范围 |
| `label_basis`、`verification_status` | 人工判断依据与已取得的验证状态，未知必须明确标注 |
| `source_uri`、`license_note`、`content_hash` | 数据来源、使用条件与去重依据 |

工具返回和用户提示默认不计算训练损失；目标是学习正确动作，而非复述观察结果。
保留真实特殊 token、角色边界和工具调用结构的能力，必须通过选定 tokenizer 与模板核实。
长片段按完整动作及其依赖拆分，不能截断工具参数或删除决定正确动作的关键信息。

## 预计文件与模块职责

以下路径是未来实现位置，本轮只交接设计，不创建功能代码或运行脚本。

| 预计路径 | 职责 |
| --- | --- |
| `configs/training/004-targeted-lora.yaml` | 基座标识、目标行为、数据版本、LoRA 参数和训练资源配置 |
| `src/training/trajectory_data.py` | 读取官方轨迹，转换上述研究字段，保留来源并按固定划分筛选 |
| `src/training/chat_encoding.py` | 套用已核实模板，生成 token 与损失掩码，处理工具消息边界 |
| `src/training/lora_training.py` | 构建冻结基座和 LoRA，运行 SFT，保存训练参数与实际资源记录 |
| `src/training/adapter_export.py` | 导出独立 PEFT adapter，汇总名称、rank、模块与实际文件大小 |
| `data/processed/004/` | 保存样本、划分清单、去重记录及来源清单，作为研究数据而非提交内容 |
| `artifacts/004/` | 保存候选 adapter、配置副本、模型版本和手动运行产物索引 |
| `agent/adapters/targeted_lora/` | 在 001 的提交目录中放入最终选定 adapter，并让根配置引用 `targeted_lora` |

训练数据流为：原始轨迹 → 目标行为筛选 → 去重与固定划分 → 模板编码与损失掩码 → SFT → 独立 adapter。
推理数据流为：同一任务输入 → 固定 Agent 配置与 QAT 基座 → 有或无 adapter → 官方补丁和评测产物。
研究配置中的自定义字段不写入 `agent.yaml`；训练模块也不作为比赛 Python 入口提交。

## 实现顺序：先确认兼容，再扩大数据

1. 从 001 选择目标并写出判定标准，人工检查约 10–20 条候选片段是否具有一致含义。
2. 对照指定 QAT 模型，核实训练基座来源、张量名称、目标层、tokenizer、聊天模板与导出格式。
3. Google 通用 QLoRA 教程采用 BitsAndBytes NF4，不能据此认定其输出适配指定 QAT compressed-tensors 模型。
4. 若不能直接训练指定量化基座，先记录替代训练基座与正式基座的差异；未经验证不宣称等价。
5. 人工运行极小规模训练与 adapter 导出，检查冻结参数、有效损失片段和 adapter 实际包含的模块。
6. 在正式 QAT 基座及官方服务配置上人工确认 adapter 被加载、请求被路由到它，且工具调用可执行。
7. 只有加载链路和行为输入输出均有实测证据后，才训练约 50–100 条去重示例的首个研究版本。
8. 首轮可从低 rank 候选 8 或 16 中选择一个，其他参数依据实际资源固定并记录，不同时搜索多个超参数。
9. 不新增特殊 token，不默认保存或训练完整 embedding、lm_head，也不把合并后的完整权重当作 LoRA 提交。

## 3. 阶段 0：用少量工作获得可信的新起点

### 0A. 固定真实执行版本与调用合同

实现一个研究侧 preflight，不改官方裁判或提交运行时：

- 记录 tasks、图、embedding、wheel、模型 config/tokenizer/chat template 的指纹；记录实际导入路径与工具 schema。
- 记录发送给模型的真实参数摘要：最大输出、是否 thinking、上下文上限、压缩设置；不只保存 YAML。
- 用无任务答案的合成小例子验证：工具消息含引号、反斜杠、换行、Unicode 时如何进入模型；编辑同类文本能否精确往返。
- 在启动模型后用最小请求确认跨工具调用 reasoning 是否留存；检查服务端实际渲染/编码后的prompt是否包含合成标记。仅看到请求中的reasoning_content或模型自述记得，不算留存证据。无法取得服务端渲染时记“转发已证、最终渲染未知”。这是兼容性探针，不计入修复成绩，不必在可提交包内实现服务中间层。
- 当前 notebook 的 compaction interval=15，归档官方 README 对正式 inference 的描述为 5；核验当前版本。压缩器是 host App 配置，不属于可随意提交的 Agent YAML 参数。本地修改必须明确标为诊断，不能冒充最终提交改进。
- 修复前后使用新 run_id 和完整 manifest，禁止把新旧环境的单次结果拼成一次配对。

**验收**：版本/模型请求/工具输入输出实际生效证据齐全；不能确认正式部署时将其列为边界，仍可做当前冻结公开环境内的比较。

### 0B. 校准验证子集，保留原始面板分母

CPU 使用官方验证入口对已经暴露的 24 题做空补丁与参考补丁对照，先检查已知异常题。参考补丁仅在分析/裁判侧使用。

- 记录空补丁是否失败、参考补丁是否通过、目标测试是否被收集和执行、依赖/fixture 错误、实际验证时长。

- 不为让任务通过而删除测试、改断言或向 Agent 注入参考补丁。

**验收**：资格由 Agent 对照结果未知前的环境事实确定。未校准任务保留“未知”，不能自动排除或算已解决。

### 0C. 第一项 GPU 对照只改变最大输出

优先候选：`max_output_tokens: 16384 → 8192`；thinking 保持当前 A0 设置。8192 是待验证候选，不是已经证明的最优值。它将可容纳输入的理论余量从约 16K 提至约 24K，但还需计算真实工具/schema/template 开销；也可能截断长回答，必须记录 finish_reason。

选择依据是前述1437步历史输出最大6114，P95约1063、P99约2255，成功轨迹205步最大1494。这支持将8192作为容量消融的初值，不保证未来不会截断，也不意味着单步生成必然提速。

- 从现有已暴露题中，事先选 6 题：至少含 `rich_3942` 上下文故障例、稳定成功例、迟编辑/工具失败例、FastAPI 与 Requests 的可验证例；资格检查后冻结名单和替换规则。
- 每题两组各运行两次：6×2×2=24 attempts，次序均衡并冻结；不能只补跑胜负翻转题。
- 两组只改最大输出，其余模型、提示词、预算、工具、版本、压缩条件一致；旧 P003 成绩不替代新对照。
- 指标：resolved 配对、上下文异常、输出截断、成功源码编辑与首次成功编辑时间、生成阶段耗时；主动提交只作过程指标。
- 若 8192 消除了上下文故障且未损害修复/截断，则可作为候选公共底座进入下一阶段；6题结果只支持筛选。正式采用需扩大面板确认。
- 若剩余失败主要是推理长、无有效动作，再单独做 thinking on/off；不能同时改最大输出和 thinking 后把收益归因任一项。

**停止条件**：出现新的长度截断/工具 JSON 不完整/服务参数不生效，先查原始请求，不继续扩大量跑。

## 4. 阶段 1：把“定位”落实成可提交的执行能力

### 1A. 先审核索引，不默认 embedding 有用

在已有开发题上进行 CPU 审核：

- 比较图节点与源码中的函数、类、`async def` 覆盖，检查源码/commit 是否一致。
- 检查短符号歧义、查询是否仅支持节点名、返回邻居是否含所需方向和位置。
- embedding 检查维度、有限值、重复向量、随机对相似度与 top-k 区分度。
- 正常定位查询只能取 issue、允许 hints 与工作区；参考补丁只在离线标注相关位置时使用。
- 使用 gold symbol 查询属于索引覆盖诊断，不能算真实 issue 检索成绩。
- 社区关于向量塌缩和 async 缺失的结果只是线索，不替代本项目实测。

本次已取得两个开发快照的官方图/embedding下载入口，但文件下载受HTTP 429限制，有限重试后停止。因而本次没有新的图覆盖率、向量相似度或检索召回实测；不得在交接时将社区数字填入本项目结果。

若覆盖/区分度不足，保留图邻域作为可选补充，跳过强制相似检索组；不要为遵守旧三组计划浪费 GPU。

### 1B. 主候选为文本 + AST 的有限输出导航 skill

官方规则与源码允许在 `skills/` 中提交脚本，经 `run_skill_script` 在工作区沙箱内运行。先做单 Agent + 确定性辅助，不引入新的模型服务。

建议接口职责（具体签名须以实际注册 schema 为准）：

1. 符号/文件查找：输入 issue 中已有标识符，输出候选路径、符号、起止行与简短片段；匹配含异步函数。
2. 相关位置扩展：从已确认符号查定义、引用或调用候选，注明静态近似和歧义；不把同名命中当精确调用关系。
3. 精确读取：按指定区间、输出上限读取；返回真实显示边界、是否截断及下一段位置。
4. 修改前/提交前检查：检查预期文件、源码 diff、语法、`git diff --check`、临时/测试文件混入；只返回报告，默认不自动删除文件或提交补丁。

脚本应只依赖可用标准库，限制扫描范围、文件大小、候选数和输出长度。候选建议最多8个、脚本自行限制输出约4000字符，作为初值并实测技能返回路径；普通run_command的5000字符截断不能泛化为技能工具的已证统一限制。临时分析产物写沙箱临时区，不进源码diff。不得访问官方答案、其他组工作区或宿主文件。

能力应适用于普通Python仓库，不写入针对FastAPI/Rich的题目答案、固定补丁或裁判预期。隐藏任务来自私有仓库，优化开发集仓库的专用规则不能替代跨仓库验证。

不要承诺脚本能自动保证 Agent 调用它；调用遵守程度本身要记录。也不要把字段存在当作能力存在：当前 callbacks 无 registry 时被忽略，不能依靠它实现可靠收尾或自定义 host hook。

### 1C. 将有效编辑单独计量

- 分开记录：正确位置首次被看见、形成可检验假设、首次尝试编辑、首次工具确认成功编辑、最终生产 diff、目标验证结果。
- 对 `old_string not found` 必须回读真实源码并检查 escaping、范围、旧文本是否真实存在；不盲目重复原参数。
- 若实现安全替换脚本，应校验文件和旧片段/哈希，歧义或不匹配时拒绝，不进行猜测性反转义或大范围替换。

- 复用一次模型服务，逐题重置沙箱、会话和attempt目录。次序均衡；共享前缀缓存不声称完全公平。

- 当前公开榜头部分数约0.17/0.15，仅为9月30日快照；私库任务、约60题公开分区及环境改动使其不能与本地12.5%横比。
- 准备一个冻结且完整的正式基线包，用一次受控正式提交校准端到端运行和公开分数；不要靠每天改一点提示词追榜。当前本账号提交查询未返回记录，本次未取得可用于对齐的已有正式分数。
- 每日最多1次、最多选2个最终提交；记录提交包指纹、评分日期/已知环境和对应开发证据。两份最终提交应依据独立证据与互补性选择，不凭公开榜小幅抖动。

## 7. LoRA 的重新进入条件

不因已有外部教师条件许可就立即启动训练。

同时满足以下条件后，开展 P004：

1. 实际 scorer 可加载 adapter，并能在本任务需要的上下文长度下完成推理；社区的LoRA/KV-cache停顿报告尚未被本项目复现或排除。
2. runtime/tool编码/验证环境已稳定，失败行为仍跨多个任务重复出现。
3. 能把目标行为写成具体标签，例如“读到正确函数后产生精确可执行编辑”，并有有效正例与反例。
4. 有合规可追溯、与确认集/heldout隔离的训练轨迹；自生成数据可优先，外部教师另核其提供方许可。
5. 先做极小训练—导出—正式量化基座加载的端到端兼容性检查，再扩大数据与训练。
6. 主验收仍是同预算下最终修复率与总成本，不以训练loss、格式成功率或主动提交率替代。

串行分析/编辑子Agent只在上下文隔离需求得到证实时另做实验；当前官方不支持并发模型调用，不能按并行加速估算收益。

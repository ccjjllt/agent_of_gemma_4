Problem Statement:
Connection.receive_data() raises RuntimeError when receiving empty data after connection close

#### Description

When calling `receive_data(b'')` (empty bytes) on a Connection that has already been closed, a RuntimeError is raised with the message "received close, then received more data?". This seems incorrect since empty data should not be considered "more data".

#### Steps/Code to Reproduce

```python
import h11

# Create a connection and close it
c = h11.Connection(h11.SERVER)
c.receive_data(b'GET / HTTP/1.1\r\nHost: example.com\r\n\r\n')
c.next_event()  # Get the request
c.next_event()  # Get EndOfMessage

# Close the connection
c.receive_data(b'')  # This should work fine

# Try to receive empty data again - this raises RuntimeError
c.receive_data(b'')  # RuntimeError: received close, then received more data?
```

The issue occurs when you call `receive_data(b'')` multiple times or after the connection has been marked as closed. Empty data should be handled gracefully and not trigger the "received more data" error since no actual data is being received.

This affects various connection scenarios including HTTP/1.0 connections, pipelined requests, and connection close handling where empty data might be received multiple times during the connection lifecycle.

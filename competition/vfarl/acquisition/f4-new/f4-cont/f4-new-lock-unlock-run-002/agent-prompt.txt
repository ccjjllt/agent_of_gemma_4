# Unlock method doesn't raise exception when called on an unlocked lock

**What happened**:
When calling `unlock()` on a lock that is not locked, the method silently returns instead of raising an exception. This can lead to unexpected behavior in code that expects an exception to be raised.

**What you expected to happen**:
The `unlock()` method should raise a `DvcException` with the message "Unlock called on an unlocked lock" when called on an unlocked lock, as it did previously.

**Steps to reproduce**:

```python
from dvc.lock import Lock
import tempfile
import os

# Create a temporary file for the lock
with tempfile.TemporaryDirectory() as tmpdir:
    lock_file = os.path.join(tmpdir, "lock")
    
    # Create a lock but don't acquire it
    lock = Lock(lock_file)
    
    # This should raise an exception but doesn't
    lock.unlock()
    
    # No exception is raised, execution continues here
    print("This line should not be reached if an exception was raised")
```

**Actual behavior**:
The code executes without raising an exception, and the print statement is executed.

**Expected behavior**:
The code should raise a `DvcException` with the message "Unlock called on an unlocked lock" when `lock.unlock()` is called.

This change in behavior could cause issues in code that relies on the exception being raised to detect improper lock usage.

Problem Statement:
# ThreadPoolExecutor's cancel_on_error parameter not working

I noticed that the `cancel_on_error` parameter in the `ThreadPoolExecutor` class doesn't seem to be working properly. When using the executor as a context manager and an error occurs, it should cancel pending futures if `cancel_on_error=True` was specified.

## Reproduction

Here's a simple example that demonstrates the issue:

```python
from dvc.utils.threadpool import ThreadPoolExecutor
import time

def raise_error():
    raise RuntimeError("This is an error")

# This should cancel pending futures when an error occurs
executor = ThreadPoolExecutor(max_workers=2, cancel_on_error=True)

with executor:
    # Submit some work
    future1 = executor.submit(lambda x: x * 2, 21)  # This completes quickly
    future2 = executor.submit(time.sleep, 0.5)      # This takes longer
    
    # Submit a task that will raise an error
    future3 = executor.submit(raise_error)
    
    # Submit more tasks that should be cancelled when future3 fails
    futures = [executor.submit(time.sleep, 0.2) for _ in range(10)]
    
    # This will complete successfully
    print(f"Result of future1: {future1.result()}")
    
    try:
        # This will raise an error
        future3.result()
    except RuntimeError:
        # Check if the other futures were cancelled
        print(f"Number of cancelled futures: {sum(1 for f in futures if f.cancelled())}")
```

Expected behavior: When the error occurs in `future3`, the remaining futures should be cancelled because we set `cancel_on_error=True`.

Actual behavior: The futures are not being cancelled when an error occurs.

I think there might be an issue with how the `cancel_on_error` parameter is being handled in the context manager.

Problem Statement:
Connection.trailing_data returns incorrect buffer data after protocol switch

#### Description

When using `Connection.trailing_data` after a protocol switch, the returned buffer data is truncated and the closed status is inverted. This affects protocol switching scenarios where you need to access the remaining data in the receive buffer.

#### Steps/Code to Reproduce

```python
import h11

# Create a server connection
conn = h11.Connection(h11.SERVER)

# Simulate receiving a CONNECT request with trailing data
conn.receive_data(b'CONNECT example.com:443 HTTP/1.1\r\nHost: foo\r\nContent-Length: 1\r\n\r\n1')

# Process the request
request = conn.next_event()
body = conn.next_event()
end = conn.next_event()

# Send acceptance response to switch protocols
conn.send(h11.Response(status_code=200, headers=[]))

# Add some trailing data after protocol switch
conn.receive_data(b'123456')

# Check trailing data - this should return the full buffer
buffer, closed = conn.trailing_data
print(f"Buffer: {buffer}")
print(f"Closed: {closed}")

# Expected: Buffer should be b'123456', closed should be False
# Actual: Buffer is truncated and closed status is wrong
```

The `trailing_data` property should return the complete buffer contents and correct closed status, but currently returns truncated data with inverted closed flag.

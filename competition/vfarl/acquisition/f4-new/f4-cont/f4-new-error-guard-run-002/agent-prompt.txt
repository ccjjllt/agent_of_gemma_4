Problem Statement:
# Connection.receive_data doesn't check for ERROR state

When trying to receive data from a connection that is already in an ERROR state, the library doesn't properly prevent further operations.

## Reproduction

Here's a simple example that demonstrates the issue:

```python
from h11 import Connection, CLIENT, RemoteProtocolError

# Create a connection
conn = Connection(our_role=CLIENT)

# Send invalid data to trigger an error
conn.receive_data(b'gibberish\r\n\r\n')

# This will raise a RemoteProtocolError and set their_state to ERROR
try:
    conn.next_event()
except RemoteProtocolError:
    pass

# This should fail but doesn't - the connection allows receiving more data
# even though the peer is in ERROR state
conn.receive_data(b'more data')
```

The problem is that when a connection's peer is in the ERROR state, the library should prevent further receive operations, but it currently allows them. This can lead to unexpected behavior since processing should have stopped after the error was detected.

The connection should reject any attempts to receive more data once the peer state is ERROR, similar to how it rejects sending data when in an error state.

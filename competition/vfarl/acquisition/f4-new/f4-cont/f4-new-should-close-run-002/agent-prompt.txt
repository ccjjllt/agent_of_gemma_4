Problem Statement:
Response.should_close() always returns True after recent changes

#### Description

The `should_close()` method in the Response class is now always returning `True`, causing connection handling issues. This breaks proper HTTP connection management where connections should remain open in certain scenarios.

#### Steps/Code to Reproduce

```python
from gunicorn.http.wsgi import Response
import mock

# Create a mocked request and socket
mocked_socket = mock.MagicMock()
mocked_request = mock.MagicMock()
mocked_request.should_close.return_value = False

# Test with a 200 status code - should not close
response = Response(mocked_request, mocked_socket, None)
response.status_code = 200
response.response_length = 100
response.chunked = False
response.must_close = False

print("Expected: False")
print("Actual:", response.should_close())

# Test with HEAD request - should not close  
mocked_request.method = 'HEAD'
response2 = Response(mocked_request, mocked_socket, None)
response2.status_code = 200
response2.must_close = False

print("Expected: False") 
print("Actual:", response2.should_close())
```

The method now ignores important conditions like `must_close`, `response_length`, `chunked`, and request method, always returning `True` for most status codes.

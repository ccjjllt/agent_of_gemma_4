Problem Statement:
SSHClient.close() raises AttributeError when called after transport is closed

#### Description

When calling `close()` on an SSHClient instance, an AttributeError is raised if the transport or agent has already been closed or set to None.

#### Steps/Code to Reproduce

```python
import paramiko

client = paramiko.SSHClient()
client.set_missing_host_key_policy(paramiko.AutoAddPolicy())

# Connect to a server
client.connect('hostname', username='user', password='pass')

# Close the client
client.close()

# Calling close again raises AttributeError
client.close()  # This should not raise an error
```

The error occurs because the code tries to call methods on `None` objects after they've been set to `None` in the close method.

#### Expected Behavior

Calling `close()` multiple times should be safe and not raise any exceptions, similar to how file objects and other resources work in Python.

#### Actual Behavior

```
AttributeError: 'NoneType' object has no attribute 'close'
```

This makes it difficult to use SSHClient in contexts where cleanup might be called multiple times, such as in finally blocks or context managers.

Problem Statement:
BufferedPipe event state incorrect when buffer is empty but not closed

#### Description

When using `select()` on a channel that has been closed by the remote end but still has an empty buffer, the event state is incorrectly set to `clear` instead of `set`, causing `select()` to not detect the channel as ready for reading even though it should be readable (to detect the EOF condition).

#### Steps/Code to Reproduce

```python
import paramiko
import select
import time

# Setup SSH connection and channel
client = paramiko.SSHClient()
client.set_missing_host_key_policy(paramiko.AutoAddPolicy())
# ... connect to server ...

# Open a channel and invoke shell
chan = client.get_transport().open_session()
chan.invoke_shell()

# Server closes the channel
# ... server-side close happens ...

time.sleep(0.1)  # Allow close to propagate

# This should return the channel as ready for reading (to detect EOF)
# but it doesn't due to incorrect event state
r, w, e = select.select([chan], [], [], 0.1)
print(f"Ready for reading: {r}")  # Expected: [chan], Actual: []
```

The issue occurs when the buffer is empty (`len(self._buffer) == 0`) but the pipe is closed. In this case, the event should be set to indicate that the channel is ready for reading (so that EOF can be detected), but instead it gets cleared.

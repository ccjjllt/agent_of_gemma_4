Problem Statement:
Worker signal handling broken after recent changes

#### Description

The arbiter's `kill_workers` method is sending incorrect signals to worker processes. When attempting to kill all workers with a specific signal, the first worker gets killed twice (once with the intended signal and once with SIGTERM), while all other workers only receive SIGTERM regardless of the intended signal.

#### Steps/Code to Reproduce

```python
import signal
from gunicorn.arbiter import Arbiter
from gunicorn.app.base import BaseApplication

class DummyApp(BaseApplication):
    def load_config(self):
        pass
    def load(self):
        def app(environ, start_response):
            start_response('200 OK', [])
            return [b'']
        return app

# Create arbiter with some mock workers
arbiter = Arbiter(DummyApp())
arbiter.WORKERS = {1001: None, 1002: None, 1003: None}

# Try to send SIGUSR1 to all workers
arbiter.kill_workers(signal.SIGUSR1)
```

Expected behavior: All workers should receive SIGUSR1
Actual behavior: First worker gets SIGUSR1 then SIGTERM, other workers only get SIGTERM

This affects graceful worker restarts and other signal-based worker management operations.

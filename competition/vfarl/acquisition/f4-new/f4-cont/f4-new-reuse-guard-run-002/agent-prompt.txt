Problem Statement:
# Connection state not properly validated when starting a new cycle

I've found an issue with the `start_next_cycle()` method in the `ConnectionState` class. The method is supposed to reset the connection state to start a new request/response cycle, but it doesn't properly validate the current state before doing so.

## Expected Result

The method should only reset the connection state if both client and server are in the DONE state, and should raise a `LocalProtocolError` otherwise.

## Actual Result

The method resets the client and server states to IDLE individually if they are in the DONE state, without checking if both are in DONE state. This allows resetting the connection state when it's not in a reusable state.

## Reproduction Steps

```python
from h11 import ConnectionState, Request, Response, EndOfMessage, ConnectionClosed
from h11._events import _SWITCH_UPGRADE
from h11._state import CLIENT, SERVER, IDLE, DONE

# Create a connection state
cs = ConnectionState()

# Process a partial request/response cycle
cs.process_event(CLIENT, Request)
cs.process_event(CLIENT, EndOfMessage)

# Try to start a new cycle when server is not in DONE state
# This should raise an error but doesn't
cs.start_next_cycle()

# Check the states - client is now IDLE but server is still in its previous state
print(cs.states)  # Not both IDLE as expected
```

The issue also affects cases where keep-alive is disabled or when a connection is closed, allowing state transitions that should be prohibited.

- Python version: 3.10
- h11 version: latest from main branch

This behavior breaks the HTTP connection state management and can lead to unexpected protocol errors when reusing connections that aren't in a proper state for reuse.

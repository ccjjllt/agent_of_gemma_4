Problem Statement:
WebSocket connections are not timing out correctly

I've noticed an issue with the WebSocket timeout logic in Daphne. The conditions for timing out WebSocket connections seem to be inverted, causing connections to behave incorrectly.

### Steps to reproduce

1. Create a WebSocket server with Daphne with a timeout configured
2. Connect to the WebSocket server
3. Wait longer than the configured timeout
4. Try to send a message

### Expected behavior

The WebSocket connection should close after the configured timeout period.

### Actual behavior

The WebSocket connection remains open indefinitely, even after the timeout period has passed. Additionally, the auto-ping mechanism doesn't seem to be working correctly.

Here's a simple reproduction script:

```python
import asyncio
import websockets
import time

async def test_websocket_timeout():
    # Connect to a Daphne server with timeout=1
    async with websockets.connect('ws://localhost:8000/ws/') as websocket:
        # Wait longer than the timeout
        print("Connected, waiting 2 seconds...")
        await asyncio.sleep(2)
        
        # This should fail if timeout is working correctly
        print("Sending message after timeout...")
        await websocket.send("still alive?")
        
        # We shouldn't receive this response if timeout is working
        response = await websocket.recv()
        print(f"Received: {response}")
        print("Connection is still alive when it should have timed out!")

asyncio.run(test_websocket_timeout())
```

The issue appears to be in the timeout checking logic in the WebSocketProtocol class. The conditions for determining when to close a connection seem to be reversed.

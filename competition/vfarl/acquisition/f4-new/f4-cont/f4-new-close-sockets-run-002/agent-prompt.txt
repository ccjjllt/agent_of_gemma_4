Problem Statement:
# Unix socket files not being unlinked when closing sockets

**Describe the bug**
When using Unix sockets with Gunicorn, the socket files are not being properly unlinked when the server shuts down. This leaves stale socket files in the filesystem.

**To Reproduce**
Steps to reproduce the behavior:
1. Create a simple WSGI application
2. Run Gunicorn with a Unix socket binding
3. Stop Gunicorn
4. Notice that the socket file still exists in the filesystem

```python
# Example reproduction script
import os
import socket
import time

# Create a Unix socket
sock_path = '/tmp/test_gunicorn.sock'
if os.path.exists(sock_path):
    os.unlink(sock_path)

# Create a socket and bind it
s = socket.socket(socket.AF_UNIX, socket.SOCK_STREAM)
s.bind(sock_path)

# Import the close_sockets function
from gunicorn.sock import close_sockets

# Close the socket using the function
close_sockets([s], unlink=True)

# Check if the socket file still exists
if os.path.exists(sock_path):
    print(f"ERROR: Socket file {sock_path} still exists!")
    print(f"Expected: Socket file should be removed")
else:
    print("SUCCESS: Socket file was properly unlinked")
```

**Expected behavior**
When Gunicorn shuts down, it should unlink (remove) the Unix socket files it created.

**Environment info**
- OS: Linux
- Python version: 3.10
- Gunicorn version: latest

**Additional context**
This issue can cause problems when trying to restart Gunicorn, as it may fail to bind to the socket if the file still exists from a previous run.

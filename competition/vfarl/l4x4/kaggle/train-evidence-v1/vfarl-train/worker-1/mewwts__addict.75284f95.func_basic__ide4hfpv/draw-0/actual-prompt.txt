Problem Statement:
Dict.copy() behavior changed in latest version, now performs a deep copy instead of a shallow copy

When using the `copy()` method on a Dict object, it now performs a deep copy instead of a shallow copy, which breaks expected behavior.

Minimal example to reproduce:

```python
from addict import Dict

# Create a nested dictionary
d = Dict()
d.a = {'value': 21}

# Create a copy
d_copy = d.copy()

# Modify the original
d.a['value'] = 42

# Check values
print(d.a['value'])  # 42
print(d_copy.a['value'])  # Expected: 42 (for shallow copy), but now returns 21
```

The expected behavior (and previously implemented behavior) is that `copy()` would perform a shallow copy, meaning changes to nested objects in the original would be reflected in the copy. This is consistent with Python's built-in `dict.copy()` method.

Now `copy()` behaves exactly like `deepcopy()`, which is redundant and breaks backward compatibility with code that expects the standard shallow copy behavior.

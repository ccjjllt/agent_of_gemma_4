Problem Statement:
M() accepts invalid specs without proper validation

When using `M()` to wrap subspecs for comparison operations, invalid specs are silently accepted instead of raising a `TypeError`. This causes unexpected behavior where the matching logic fails to work correctly.

#### Steps/Code to Reproduce

```python
from glom import glom, M, T

# This should raise TypeError but doesn't
try:
    result = M('failure')  # String is not a valid T-style spec
    print("No error raised - this is wrong!")
except TypeError as e:
    print(f"Expected error: {e}")

# This also demonstrates the issue in practice
target = {'a': 1, 'b': 2}
spec = M(T['a']) < M(T['b'])  # This should work
result = glom(target, spec)
print(f"Valid spec result: {result}")

# But invalid specs don't get caught
invalid_spec = M('not_a_spec')  # This should fail but doesn't
print(f"Invalid spec created: {invalid_spec}")
```

The issue appears to be that `M()` is not properly validating that the provided spec is a T-style spec before wrapping it, allowing invalid specifications to pass through the validation step.

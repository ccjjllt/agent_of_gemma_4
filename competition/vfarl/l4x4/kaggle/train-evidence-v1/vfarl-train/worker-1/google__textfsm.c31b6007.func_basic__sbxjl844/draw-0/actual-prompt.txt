Problem Statement:
# Records in List values are being reversed

## Description

When using List values in TextFSM templates, the records are being stored in reverse order. This affects any template that uses the List option for Values.

For example, if I have a template like:
```
Value List foo (some_pattern)

Start
  ^${foo} -> Record
```

And input text with multiple matches, the resulting list will have the items in reverse order compared to how they appear in the input text.

This is causing issues in our parsing logic where we expect the items to be in the same order as they appear in the input text. Before this change, the order was preserved correctly.

This affects both simple List values and more complex ones with nested capture groups.

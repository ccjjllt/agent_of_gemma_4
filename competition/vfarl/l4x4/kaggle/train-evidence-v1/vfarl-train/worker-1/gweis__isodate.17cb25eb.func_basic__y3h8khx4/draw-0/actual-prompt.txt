Problem Statement:
Duration.totimedelta() fails when both start and end parameters provided

#### Description

The `totimedelta()` method in the Duration class doesn't properly handle the case when both `start` and `end` parameters are provided. Instead of raising a ValueError as expected, it silently accepts both parameters and produces incorrect results.

#### Steps/Code to Reproduce

```python
from isodate import Duration
from datetime import datetime, timedelta

# Create a simple duration
dur = Duration(days=10)

# This should raise ValueError but doesn't
start_date = datetime(2023, 1, 1)
end_date = datetime(2023, 1, 15)

# Both parameters provided - should raise ValueError
result = dur.totimedelta(start=start_date, end=end_date)
print(f"Result: {result}")  # Should not reach here
```

Expected behavior: Should raise `ValueError("only start or end allowed")` when both start and end are provided.

Actual behavior: Method executes without error and returns an incorrect timedelta value.

The method also produces wrong calculations when only one parameter is provided, giving unexpected results for duration conversions.

Problem Statement:
# IndexError not raised when accessing non-existent child element by index

### What happened?

When trying to access a non-existent child element by index in a DOM tag, a KeyError is being caught and converted to an IndexError, but the exception handling is incorrect. The code is catching a KeyError when it should be catching an IndexError.

### What did you expect to happen?

When accessing a non-existent child element by index (e.g., `div_element[10]` when there are no children), an IndexError should be raised with the message "Child with index "X" does not exist."

### Minimal Complete Verifiable Example

```python
from dominate.tags import div

# Create an empty div
d = div()

# Try to access a non-existent child element
d[10]  # This should raise an IndexError
```

### Relevant log output

```
KeyError: 10
```

Instead of the expected:

```
IndexError: Child with index "10" does not exist.
```

### Anything else we need to know?

The issue is in the `__getitem__` method of the `dom_tag` class. When trying to access a child element by index, the code is catching the wrong exception type, which causes unexpected behavior when accessing non-existent children.

This affects any code that relies on catching IndexError when accessing non-existent children in DOM elements.

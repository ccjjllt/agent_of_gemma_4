Problem Statement:
# stop_after_delay not working correctly with exact delay value

I'm using the `stop_after_delay` feature in tenacity and noticed that it's not behaving as expected when the elapsed time exactly matches the specified delay.

## Reproduction

I have code that uses `stop_after_delay` like this:

```python
from tenacity import Retrying, stop_after_delay
import time

r = Retrying(stop=stop_after_delay(1))  # stop after 1 second

# This should stop retrying when exactly 1 second has passed
start_time = time.time()
for attempt in r:
    with attempt:
        elapsed = time.time() - start_time
        print(f"Attempt {attempt.retry_state.attempt_number}, elapsed: {elapsed:.3f}s")
        if elapsed < 1.0:
            raise Exception("Not ready yet")
        print("Success!")
```

## Expected behavior

The retry should stop when the elapsed time is greater than or equal to the specified delay (1 second in this case).

## Actual behavior

The retry only stops when the elapsed time is strictly greater than the specified delay. When the elapsed time is exactly equal to the delay, it continues retrying.

This seems like a bug because if I specify a delay of 1 second, I would expect the operation to stop retrying once 1 second has passed, not after 1.00...1 seconds.

I also tried using a `datetime.timedelta` object instead of a number for the delay parameter, but the behavior is the same.

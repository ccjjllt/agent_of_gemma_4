Problem Statement:
Table.truncate() doesn't properly clear table data

#### Description

After calling `truncate()` on a table, the table data is not properly cleared and the document ID counter is not reset correctly. The `_get_next_id()` method returns 0 instead of the expected 1 after truncation.

#### Steps/Code to Reproduce

```python
from tinydb import TinyDB
from tinydb.storages import MemoryStorage

# Create a database and table
db = TinyDB(storage=MemoryStorage)
table = db.table('test')

# Insert some data
table.insert({'name': 'Alice'})
table.insert({'name': 'Bob'})

# Truncate the table
table.truncate()

# Check next ID - should be 1 but returns 0
print(f"Next ID after truncate: {table._get_next_id()}")  # Expected: 1, Actual: 0

# Try getting multiple IDs
print(f"Second ID: {table._get_next_id()}")  # Expected: 2, Actual: 1
print(f"Third ID: {table._get_next_id()}")   # Expected: 3, Actual: 2
```

The issue affects both memory and JSON storage backends. After truncation, the ID sequence starts from 0 instead of 1, which breaks the expected behavior where document IDs should start from 1.

Problem Statement:
# Val() with None value is being converted to 0

I noticed an issue with the `Val` class in glom. When using `Val(None)` in a complex expression, it's being converted to `0` instead of preserving the `None` value.

Here's a simple reproduction:

```python
from glom import glom, Val

# This should return None, but returns 0 instead
result = glom({}, Val(None))
print(result)  # Outputs: 0

# This affects more complex expressions too
from glom import Match, Ref, Or, And

# Using Val(None) in a Match expression
data = {'a': {'b': [0, 1]}}
spec = Ref('json', Match(Or(
    And(dict, {Ref('json'): Ref('json')}),
    And(list, [Ref('json')]),
    And(0, Val(None)),  # This should return None for 0 values
    object
)))

result = glom(data, spec)
print(result)  # The 0 in the list gets converted to 0 instead of None
```

I think the `Val` class should preserve the exact value it's given, including `None`, rather than converting it to `0`. This seems like a regression that could break existing code that relies on `Val(None)` returning `None`.

Problem Statement:
# HTML table parsing issue with PrettyTable

I've found an issue with the HTML table parsing functionality in PrettyTable. When trying to convert an HTML table back to a PrettyTable object, it's not working correctly.

## Description

When using the `from_html()` or `from_html_one()` functions to parse an HTML table that was previously generated with `get_html_string()`, the resulting PrettyTable object doesn't match the original table.

## Steps to reproduce

```python
from prettytable import PrettyTable, from_html, from_html_one

# Create a table
table = PrettyTable()
table.field_names = ["City name", "Area", "Population", "Annual Rainfall"]
table.add_row(["Adelaide", 1295, 1158259, 600.5])
table.add_row(["Brisbane", 5905, 1857594, 1146.4])
table.add_row(["Darwin", 112, 120900, 1714.7])

# Convert to HTML
html_string = table.get_html_string()

# Try to convert back
new_table = from_html(html_string)[0]  # This doesn't match the original
# OR
new_table = from_html_one(html_string)  # This also doesn't match the original

# Verify
print(new_table.get_string() == table.get_string())  # Returns False
```

The issue seems to be related to how the HTML parser is handling table headers. When examining the HTML parsing code, I noticed that it's looking for "th" tags to identify headers, but something is going wrong in the process.

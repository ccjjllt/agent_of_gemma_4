Problem Statement:
Schema equality comparison broken for schemas with same name but different parents

#### Description

Schema objects with the same name but different parent schemas are incorrectly considered equal, and schemas with different names but same parent are also incorrectly considered equal.

#### Steps/Code to Reproduce

```python
from pypika import Schema, Table

# Case 1: Different parents, same name - should be different but are equal
parent1 = Schema('parent1')
parent2 = Schema('parent2')
schema_a1 = Schema('a', parent=parent1)
schema_a2 = Schema('a', parent=parent2)

print(f"schema_a1 == schema_a2: {schema_a1 == schema_a2}")  # Should be False but returns True

# Case 2: Same parent, different names - should be different but are equal  
parent = Schema('parent')
schema_a = Schema('a', parent=parent)
schema_b = Schema('b', parent=parent)

print(f"schema_a == schema_b: {schema_a == schema_b}")  # Should be False but returns True

# Case 3: Tables using these schemas also affected
t1 = Table('t', schema=schema_a1)
t2 = Table('t', schema=schema_a2)

print(f"t1 == t2: {t1 == t2}")  # Should be False but returns True
```

Expected output:
```
schema_a1 == schema_a2: False
schema_a == schema_b: False
t1 == t2: False
```

Actual output:
```
schema_a1 == schema_a2: True
schema_a == schema_b: True
t1 == t2: True
```

This affects table equality comparisons when tables have schemas, making it impossible to properly distinguish between tables in different schema hierarchies.

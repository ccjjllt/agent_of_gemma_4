Problem Statement:
# Security vulnerability in YAML loading

I found a security issue in the glom CLI when processing YAML files. The CLI is using `yaml.load()` instead of `yaml.safe_load()` which creates a potential security vulnerability.

When using the CLI with YAML files, I noticed that it's now possible to execute arbitrary code through specially crafted YAML files. This is a known security issue with PyYAML when using the unsafe `load()` function.

## Steps to reproduce

1. Create a malicious YAML file (example.yaml):
```yaml
!!python/object/apply:os.system
- echo "This could be malicious code execution"
```

2. Use the glom CLI with this file:
```
glom example.yaml '{"data": "value"}'
```

The command will execute the code in the YAML file rather than just loading it as data.

## Expected behavior

The CLI should use `yaml.safe_load()` which prevents code execution and only loads safe data types.

## Actual behavior

The CLI uses `yaml.load()` which allows arbitrary code execution through YAML files, creating a security vulnerability.

This is particularly dangerous since users might process untrusted YAML files with the glom CLI, not expecting that this could lead to code execution on their system.

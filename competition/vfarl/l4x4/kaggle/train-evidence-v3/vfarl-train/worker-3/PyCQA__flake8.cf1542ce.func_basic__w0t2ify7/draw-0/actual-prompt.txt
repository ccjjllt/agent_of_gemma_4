Problem Statement:
Error code selection logic inverted when both explicit and implicit selections present

#### Description

When using flake8 with both explicit error code selections (like `--select E111,E121`) and implicit selections, the decision logic for determining which errors to report appears to be inverted. Error codes that should be explicitly selected are being ignored, while codes that should be implicitly ignored are being selected.

#### Steps/Code to Reproduce

```python
from flake8.style_guide import DecisionEngine
from flake8.options.manager import OptionManager

# Create options with explicit selections
options = OptionManager().get_default_values()
options.select = ['E111', 'E121']
options.ignore = []
options.extend_ignore = None

decider = DecisionEngine(options)

# This should return Selected.Explicitly but doesn't
print(f"E111 decision: {decider.decision_for('E111')}")  # Expected: Selected.Explicitly

# This should return Ignored.Implicitly but doesn't  
print(f"E112 decision: {decider.decision_for('E112')}")  # Expected: Ignored.Implicitly
```

The issue manifests when you have explicit selections configured - codes that are explicitly selected get treated as if they should be ignored, and codes that should be implicitly ignored get selected instead.

This affects the core functionality of flake8's error filtering system, causing it to report the wrong set of errors when using `--select` with specific error codes.

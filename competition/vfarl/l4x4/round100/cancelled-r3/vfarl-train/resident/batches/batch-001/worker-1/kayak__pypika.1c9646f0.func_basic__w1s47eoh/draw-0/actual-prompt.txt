Problem Statement:
Table.for_portion method incorrectly validates and assigns attributes

#### Description

The `for_portion` method on Table objects has incorrect logic that prevents it from working properly. When trying to use `for_portion` with temporal queries, it raises an AttributeError even when it should be allowed.

#### Steps/Code to Reproduce

```python
from pypika import Query, Table
from pypika.terms import SYSTEM_TIME

table_abc = Table('abc')

# This should work but raises AttributeError
q = Query.from_(table_abc.for_portion(SYSTEM_TIME.from_to('2020-01-01', '2020-02-01'))).delete()
print(str(q))
```

Expected output:
```
DELETE FROM "abc" FOR PORTION OF SYSTEM_TIME FROM '2020-01-01' TO '2020-02-01'
```

Actual output:
```
AttributeError: 'Query' object already has attribute for_portion
```

The same issue occurs with update queries:

```python
q = Query.update(table_abc.for_portion(SYSTEM_TIME.from_to('2020-01-01', '2020-02-01'))).set('foo', 'bar')
print(str(q))
```

This should produce:
```
UPDATE "abc" FOR PORTION OF SYSTEM_TIME FROM '2020-01-01' TO '2020-02-01' SET "foo"='bar'
```

But instead raises the same AttributeError.

Problem Statement:
Min aggregator returns wrong value when processing duplicate minimum values

#### Description

When using the `Min()` aggregator with data containing duplicate minimum values, it returns the input value instead of the stored minimum value from the aggregation tree.

#### Steps/Code to Reproduce

```python
from glom import glom, Group, Min

# This should return 0 (the minimum value)
result = glom([1, 0, 1], Group(Min()))
print(f"Result: {result}")
print(f"Expected: 0")
```

The above code returns `1` instead of the expected `0`.

#### Expected Behavior

The `Min()` aggregator should return the actual minimum value found during aggregation, which is `0` in this case.

#### Actual Behavior

The aggregator returns `1` (the last processed value that was less than or equal to the current minimum).

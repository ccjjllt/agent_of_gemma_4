List values are reversed when several matches accumulate in one TextFSM record

A List value should retain match order within a record, including nested capture-group values. With the template below, matches accumulate until the implicit EOF record:

```python
from io import StringIO
from textfsm import TextFSM

template = r"""Value List foo (\w+)

Start
  ^${foo}
"""
result = TextFSM(StringIO(template)).ParseText("first\nsecond\n")
```

Expected: [[['first', 'second']]]. The current result is [[['second', 'first']]]. Preserve the existing record/reset behavior. A template that emits Record on every input line produces singleton lists and does not demonstrate this ordering problem.

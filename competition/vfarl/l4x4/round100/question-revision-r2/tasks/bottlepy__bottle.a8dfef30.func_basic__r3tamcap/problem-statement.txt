ConfigDict overlay chains stop receiving later source updates

Creating an overlay initially copies the source values, so the first read can succeed. The defect appears when a source value changes after child overlays already exist: that change should propagate through the overlay chain for a key that the children have not overridden.

```python
from bottle import ConfigDict

source = ConfigDict()
source["key"] = "source"
intermediate = source._make_overlay()
overlay = intermediate._make_overlay()
assert overlay["key"] == "source"

source["key"] = "source2"
assert intermediate["key"] == "source2"
assert overlay["key"] == "source2"
```

Expected: both existing child overlays see source2.
Actual: the existing overlays retain source. The initial read alone does not reproduce this propagation failure.

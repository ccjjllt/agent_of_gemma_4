Missing child indices should use the documented IndexError message

Accessing a missing integer child index on a DOM tag already raises IndexError, but the error currently has the underlying list message instead of the tag API's descriptive message.

```python
from dominate.tags import div

node = div()
try:
    node[10]
except IndexError as exc:
    assert str(exc) == 'Child with index "10" does not exist.'
else:
    raise AssertionError("A missing child index must raise IndexError")
```

Expected: the IndexError identifies the missing child index as shown above.
Actual: the exception is IndexError with the message "list index out of range". The issue is the missing descriptive message, not a missing exception or a KeyError.

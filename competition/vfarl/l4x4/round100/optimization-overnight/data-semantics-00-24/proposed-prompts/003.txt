DecisionEngine confuses explicit selection, implicit selection, and ignored codes

The selection decision should depend on both the code and the configured prefixes. Keep the two existing API layers distinct: was_selected(code) returns a Selected or Ignored enum describing selection provenance, while decision_for(code) returns the final Decision enum.

```python
from argparse import Namespace
from flake8.style_guide import Decision, DecisionEngine, Ignored, Selected

def options(select, defaults):
    return Namespace(
        select=select,
        ignore=[],
        extend_select=None,
        extend_ignore=None,
        extended_default_select=defaults,
        extended_default_ignore=[],
    )

explicit = DecisionEngine(options(["E111", "E121"], []))
assert explicit.was_selected("E111") is Selected.Explicitly
assert explicit.was_selected("E112") is Ignored.Implicitly
assert explicit.decision_for("E111") is Decision.Selected
assert explicit.decision_for("E112") is Decision.Ignored

implicit = DecisionEngine(options(None, ["E"]))
assert implicit.was_selected("E112") is Selected.Implicitly
```

Actual: the explicitly configured engine treats an unselected code such as E112 as selected; the default-prefix case is also classified as explicit rather than implicit. The expected enum values above belong to their respective methods and should not be replaced with booleans.

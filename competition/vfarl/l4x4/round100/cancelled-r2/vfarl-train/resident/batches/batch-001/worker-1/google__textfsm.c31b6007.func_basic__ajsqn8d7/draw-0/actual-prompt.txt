Problem Statement:


# TextFSM ClearAllVar bug with List values

#### Description

The `OnClearAllVar` method in `TextFSMOptions` class is initializing the `_value` list with `[None]` instead of an empty list. This causes issues when working with List-type values, especially when using nested regex capture groups.

#### Steps/Code to Reproduce

```python
import textfsm
import io

# Example 1: List values with nested regex capture groups
tplt = 'Value List foo ((?P<name>\\w+):\\s+(?P<age>\\d+)\\s+(?P<state>\\w{2})\\s*)\nValue name (\\w+)\n\nStart\n  ^\\s*${foo}\n  ^\\s*${name}\n  ^\\s*$$ -> Record'
t = textfsm.TextFSM(io.StringIO(tplt))
data = ' Bob: 32 NC\n Alice: 27 NY\n Jeff: 45 CA\nJulia\n\n'
result = t.ParseText(data)
print(result)  # Incorrect result

# Example 2: Simple List values
tplt = 'Value List boo (on.)\nValue hoo (tw.)\n\nStart\n  ^$boo\n  ^$hoo -> Next.Record\n\nEOF'
t = textfsm.TextFSM(io.StringIO(tplt))
data = 'one\ntwo\non0\ntw0'
result = t.ParseText(data)
print(result)  # Incorrect result
```

#### Expected Results

For Example 1, the result should be:
```
[[[{'name': 'Bob', 'age': '32', 'state': 'NC'}, {'name': 'Alice', 'age': '27', 'state': 'NY'}, {'name': 'Jeff', 'age': '45', 'state': 'CA'}], 'Julia']]
```

For Example 2, the result should be:
```
[[['one'], 'two'], [['on0'], 'tw0']]
```

#### Actual Results

The results include `None` values in the lists, which breaks the expected behavior of List-type values in TextFSM templates.

The issue is in the `OnClearAllVar` method in `TextFSMOptions` class, which is initializing the `_value` list incorrectly.

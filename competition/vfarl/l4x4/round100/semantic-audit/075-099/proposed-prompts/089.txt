**Namespace declarations in XML parsing are reversed**

I found a bug in the XML namespace handling. When parsing XML with namespaces, the prefixes and URIs are being swapped, causing incorrect parsing results.

For example, when I have XML like this:

```xml
<root xmlns:ns="http://example.org/ns" k="v">
  <ns:element>value</ns:element>
</root>
```

The namespace declarations are being stored incorrectly, with the URI as the key and the prefix as the value, instead of the other way around.

**To Reproduce**

Here's a simple example that demonstrates the issue:

```python
import xmltodict

xml = '''
<root xmlns:ns="http://example.org/ns" k="v">
  <ns:element>value</ns:element>
</root>
'''

# This fails to correctly handle the namespace
result = xmltodict.parse(xml, process_namespaces=True)
print(result)

# Expected output should have properly handled the namespace
# But instead the namespace mapping is reversed
```

When running this code, the namespace handling is incorrect because the prefix-to-URI mapping is reversed internally.

This affects all XML parsing where namespaces are involved, particularly when using the `process_namespaces=True` option.
In this version, inspect result['root']['@xmlns']. It should be {'ns': 'http://example.org/ns'}, but currently it is {'http://example.org/ns': 'ns'}. The regular attribute k makes the namespace-declaration metadata observable; the expanded element name itself is unchanged.
